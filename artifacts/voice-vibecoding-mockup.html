新旧对比 · 「打开应用」框架退场

旧框架让用户配置「每个 app 的语音口令」—— 2015 年的概念。新框架预置 vibecoding 场景，让用户配的是「嘴怎么说话、说给谁」。

旧 · voiceWakeKindAppPane
  • Tab 二选一：开始输入 / 打开应用
  • 每行 = 一个应用：图标 + 文字口令 + 声学状态
  • 三个按钮：录制 / 回放 / 测试
  • 「添加应用」+「在按键页管理」按钮
  • 空态：「尚未设置，请到按键页添加」
  • 用户要懂：app id、聚焦 vs 启动、声音口令

新 · vibecoding 场景入口
  • 三段式：触发方式 / vibecoding 场景 / sticky 听写条
  • 5 个出厂场景预设：Claude Code · Codex · Cursor · 通用 IDE · 前台窗口
  • 场景卡 = 图标 + 名 + 接收方 + 触发器绑定
  • 点击展开场景详情：触发方式 / 接收方 / 进程匹配
  • 侧键 push-to-talk = 主推（手不离键）
  • sticky 听写条 = Wispr 式最小化，永远在底部
  • 用户只决定：嘴 / 手怎么说话 → 默认送到对的地方
关键差异：用户不再 「加 app」，而是 「选当前在哪个场景」。 场景激活后，前台匹配 = claude → 侧键 push-to-talk 自动送到终端 TUI。
