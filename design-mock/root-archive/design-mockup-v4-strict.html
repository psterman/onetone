工具型 UI，不是设置型 UI

按 vibecoding 用户的第一性原则重构：界面 95% 的任务是"瞟一眼系统还在听"，剩下 5% 是调设置。现在的版本把比例做反了 —— 把 SETTINGS 当主屏，把 LIVE 当附属。这版反过来。

Live > Settings · 状态可视化 · 主色克制
原则：每个像素都必须服务于"我现在能不能说话"，否则删掉。

04

改动总结 · 11 处核心改动

按"为什么改"而不是"改了什么"排序
首屏主元素 5 张白色配置卡堆叠 实时识别面板（大字 + 大波形）
设置区位置 默认展开，占满首屏 默认折叠在底部，点开才出现
状态语义 1 个绿色小点常驻 idle / listening / dictating / error 四态独立色 + 动效
"工作中"主色 无 琥珀色 #FF9F0A 专属给 dictating 状态，区别于 idle 灰和 listening 蓝
蓝色用量 8 处出现（badge / button / 选中行 / accent / link） 2 处（主按钮 + 文字链接）
唤醒词展示 5 + 5 个双语 chip 铺开 单值大字号 + 切换入口，备用词只列一行
状态条 两套样式不统一 单行 32px 状态条，引擎 / 模型 / 目标 app 一行流
实时文本字号 12px 等宽体塞在卡底部 32px 主屏字号，行高 1.45，扫一眼就能纠错
右侧栏 实时 / 引擎 / 应用 三张同权重卡堆叠 实时上移成主屏，引擎 + 应用折叠进底部设置
标签字号系统 11 / 13 / 16px 三套混用 12 / 14 / 17 / 24 / 32px 五级层级，每级一用途
空状态 / 占位 无 —— 打开看到一堆设置 "按住热键开始说话" 大字号占位，按一次就消失
