01 顶部状态条 状态码 + 引擎信息 + 目标应用 + 延迟 → 借鉴 Linear 三段式
Linear 左图标 / 中信息 / 右操作
小型模型 · 本地
380ms ● VS Code
Raycast pill 横排
● DICTATING 小型 本地
VS VS Code
为什么选 Linear
voice-pilot 的状态条需要承载引擎 / 模型 / 延迟 / 目标 app / 状态码五个信息维度，三段式分区（左图标/中信息/右操作）天然适合。Linear 的"延迟放右侧高亮蓝"是经典模式。Raycast pill 排信息量小时好看，超过 4 个 pill 就挤。
借鉴 vs 自创
借鉴：左/中/右分区 + 24px 高度 + 等宽字 + 高亮蓝强调延迟
自创：把状态码 [DICTATING] 放在中间、延迟放右（参考 Terminal 风的 ASCII），比 Linear 更"信息可视化"
02 主屏实时文本 用户说什么 / 系统听到什么 → 借鉴 Claude 排版

为什么选 Claude
Claude 的思考中三点跳 + typewriter 输出是 voice-pilot 实时文本的最佳模板：用户看见字符一个个落下，确认系统在认真听。Ulysses 字体太雅，衬线字体不适合代码场景。Claude 字体用 Inter Sans + 等宽 ▎ 光标，既清晰又有质感。
关键决策
流式输出 vs 一句一更新：选流式（typewriter 效果）。识别一个字显示一个字，延迟感低 60%，用户感知不到 380ms 的真实延迟
03 波形 / 实时反馈 正在听 → 视觉化的"耳朵" → 借鉴 Raycast + Cursor 混合
Raycast 圆角 bar + 光晕
PICK
Cursor 光晕球 + 扩散环
Terminal ASCII 字符
▁▂▄▆▇█▇▅▃▂▁▂▄▆▇█▆▄▂
为什么主推 Cursor 光晕球
Raycast 的 bar 太"装饰"（用户每次看都差不多），Terminal 的 ASCII 太抽象。Cursor 光晕球 + 扩散环是"在工作中"的最强信号，2 个扩散环错峰扩散，肉眼一看就知道"在录"。原则：波形跟主题走，Raycast 风用 bar、Cursor 风用光晕球、Terminal 风用 ASCII，都靠同一个 token 切换。
三种风格并存
不是选一个，是每个主题一个：
· Terminal 主题 → ASCII ▁▃▅█
· Raycast 主题 → Raycast 圆角 bar
· Cursor 主题 → Cursor 光晕球
都引用同一个 --wave-style token
04 状态指示点 idle / listening / dictating / error 四态 → 借鉴 Linear + Terminal

IDLE

PICK
Linear + Terminal 混合 圆点 + 文字状态码
[IDLE] 待命 · 按 [Ctrl+⇧+V] 开始
[LISTENING] 唤醒词检测中
[DICTATING] 正在听 · 44 chars · 380ms
[ERROR] 引擎离线 · 5 分钟前
为什么混合
纯 Linear 小圆点在远距离不可读，纯 Terminal 文字在主屏抢戏。圆点 + 状态码文字同时出现：圆点给视觉锚点（从屏幕外缘就能扫到），文字给明确语义（近距离能读懂）。
四态的色与义
idle = 灰 6B6B6B + [IDLE] 中性灰文字
listening = 蓝 00A3FF 慢脉冲 + [LISTENING] 蓝文字
dictating = 蓝 00A3FF 快脉冲 + [DICTATING] 白文字
error = 红 FF4D6A 不脉冲 + [ERROR] 红文字
关键：listening 和 dictating 同色不同节奏，1.6s vs 1.2s 间隔区分"在等你说"和"正在录"
05 操作按钮区 结束 / 切换 / 设置 → 借鉴 Cursor 单主操作
Raycast 三个等权 pill
PICK
Cursor 1 主操作 + 2 次操作
为什么选 Cursor
Raycast 三等权设计适合"命令面板"（用户主动选择），不适合"工具面板"（系统主动建议）。voice-pilot 的核心动作只有一个："结束说话"，其他都是辅助。Cursor 的"1 大 + 2 小"分配让用户视觉上立即知道该按哪个。
细节
主操作按钮里嵌入了 hotkey 提示（松开），用户用一次就学会了，不用专门打开"快捷键面板"。次操作不放快捷键，避免视觉过载。

为什么选 Notion tray
设置是 95% 时间不需要看的。Notion tray 的好处：用户能看到"设置就在那里"（安心感），但不占主屏空间。iOS sheet 适合移动端，桌面端从底部弹出会显得突兀（鼠标从屏幕底部拖上来不自然）。
三种触发方式
方式 1：点击底部"⚙ 设置"按钮展开（最直接）
方式 2：右键主屏任意位置 → 弹出菜单（Linear 风格）
方式 3：`Ctrl+,` 快捷键直接打开（Cursor 风格）
v1 只做方式 1，其他 v2 加
07 空状态 用户第一次 / 没事干时看到什么 → 借鉴 Linear 一句话
PICK
Linear "X to start" 一句话
按住 Ctrl + ⇧ + V 开始说话
voice-pilot · 待命中 · 小型模型 · 本地
Claude 三点跳 thinking
为什么选 Linear
空状态是用户的第一个教程，必须 100% 告诉他下一步干什么。Linear 的"Press X to do Y"是教科书级空状态：用户 1 秒看懂、5 秒上手。Claude thinking 三点是"等待中"的视觉，不适合做空状态，用户会以为系统在思考什么。
三处细节
1：把热键嵌在提示里（不用单独开"快捷键面板"）
2：底部一行小字显示当前状态（小型模型 · 本地）—— 让用户知道系统在 ready
3：首次启动时显示一次 onboarding 浮窗，第二次起只显示这行（教学一次就好）
08 错误状态 引擎挂了 / 麦克风没权限 / 识别失败 → 借鉴 1Password + Wave
Wave 上下文感知报错
voice-pilot

last online: 5 min ago · during: '现在我把界面重构'

PICK
1Password + Wave 混合 风险分级 + 上下文 + 行动
引擎连接失败
5 分钟前中断于 "现在我把界面重构"。
可能是网络问题或本地模型路径错误。
为什么混合 1Password + Wave
错误状态三件事必须同时说清：1) 出了什么事 2) 在什么上下文 3) 怎么办。
1Password：图标 + 标题 + 描述 + 双按钮（主操作 + 次操作）
Wave："在 'X' 时中断了" 这种上下文让用户立刻知道刚才那段内容有没有丢
三种错误的差异化
引擎离线 = 红 + "重新连接" 按钮
麦克风没权限 = 黄 + "去设置打开权限" 按钮
识别置信度低 = 蓝（不阻断）+ 在文字底下加波浪线 + 建议重新说
