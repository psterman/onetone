Agent × 数据：四案原型

前提：皮肤 / 何时出现已收进虚拟键盘。下面四案只争一件事——vibecoding 用户的注视里，能力纵深与干活反馈如何解耦，而不是把数据卡绑在 Agent 行上。

思路：两套目录各管各的——Agent 管「怎么看见 / 怎么指挥」，数据管「今天干得怎样」。

优点是边界清晰；代价是心智来回跳，且数据墙默认按 Agent 成行 → 罗列感强。

维度 A · 平级双页 B · 同屏混合 C · 注视纵深 D · 左 Agent / 右栏
布局 两页跳转 预览里塞五镜+卡 Agent 页 + 二级数据墙 左 Agent · 右数据栏（镜切换）
用户心里的问题 配置在哪 / 报表在哪 一边改一边看数 现在 → 这轮 → 回头 同 C，且「回头」不用换页
顶栏心智 三 peer 两入口（数据吞进 Agent） 两入口 + 数据二级 两入口；数据是栏不是页
当下注视 灯 OK；用量跳页 灯被 KPI 抢 灯 / 环为主；预警条次之 左灯/环；右栏周边视觉，可扫可忽略
数据主键 Agent 行 × KPI Agent 卡 + 五镜 问题成镜 问题成镜（右栏切换）；Agent 仅筛选
少跳转 差 最好（但糊） 复盘要深链 最好且不糊：换镜不换页
罗列 / 绑卡 高 高 低 低；无源行可隐藏
窄屏 / 省空间 各占整页 一页过载 整页墙偶尔需要 右栏可折叠；深复盘再展开全墙（可选）
落地代价 低 中偏高 中 中：Agent 壳改两栏 + 右栏 bridge；可复用五镜数据

建议落 D：C 的纵深，用右栏同屏

A/B 分别死在「跳转」和「绑卡」。C 定对了三层注视与问题成镜，但复盘仍要换页。D 把数据做成右侧动态栏：左侧纪律只配看见与指挥，右侧按效率/费用/用量/时长/灵感切换问句——同屏关注，主键仍是问题不是 Agent。需要全墙时再从右栏「展开」即可，不必占顶栏 peer。
