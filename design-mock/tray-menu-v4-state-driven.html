托盘菜单重构 v4 · 全局解耦 + 优先级驱动

上一版我被"现有菜单能塞什么"困住了。重新出发：先做 8 页内容审计 → 列出 数据 × 用户关注度矩阵 → 再设计 3 个原型。 3 个原型共用同一份 TrayState 数据源，但信息架构完全不同：① 此刻能否用 ② 4 通道骨架 ③ 最近活动流。

架构要点
• Channel 是 first-class：id/icon/state/quick/deep_link
• quick action = tray 内能直接做的（如停用语音、显示软键盘）
• deep link = 必须去主页做的（如改按键绑定）
• 每个 channel 是独立订阅单元，状态变化只 patch 自己那一行
