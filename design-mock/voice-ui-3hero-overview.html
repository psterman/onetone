OneTone · 语音版块三 hero 改造方案

基于三阶段框架：开启（怎么开始打字）→ 结束（说错了想结束）→ 发送（说完了怎么发出去）。三 hero 各管一段语音会话时间轴；摄像头 / SoftPad 是并列通道，不串进开启因果链。
01
开启
怎么开始打字
从"按一个键/说一个词"到"进入听写"之间发生什么（仅语音因果链）
  • 唤醒词确认(按 F8 / 说"开始输入")
  • （可选）前台目标 — 打开 / 聚焦应用窗口
  • （可选）激活键 — 发送输入法激活键
  • 进入听写（麦克风开路）
  • 旁链：摄像头 / SoftPad → 跳转对应通道，不阻塞开启
→
02
结束
说错了想结束
正在说话过程中,随时能"停",并保留 / 取消（UI 重组轨）
  • 自动结束(静音 / VAD 阈值)
  • 手动结束(说"结束"词)
  • 取消丢弃(说"取消"词)
  • 实时显示本轮时长 / 字数 / 静音倒计时
  • 能力增量轨：触发后 2s 撤销窗口（另排期，非 P0）
→
03
发送
说完了怎么发出去
文字已经在光标处；P0 显式化既有 send_mode，增量动作另排期
  • 完成输入(只上屏,啥也不做) — 既有 send_mode=none
  • 发送 / Enter — 既有 send_mode=auto
  • 能力增量：复制到剪贴板（另排期）
  • 能力增量：触发 agent / SoftPad（另排期）
  • 能力增量：窗口智能推荐（另排期）

绑定与页面职责（钉死）

避免「通用 / 习惯 / 通道」交叉混乱；与 HABIT_UNIFIED_CONTRACT 五词对齐
表面绑定可写？说明
设置 → 语音（三 hero） selectedMappingId 可写配置 正在编辑某习惯 / 应用场景的语音通道；可与正在使用不同
首页 · 语音摘要 activeSceneId 只读投影 正在使用习惯的开启/结束/发送摘要；点卡进设置编辑，不在首页改写
摄像头 / Soft Pad 各自通道页 各通道内 并列能力；Hero① 仅旁链跳转，不进入语音因果链

实现优先级

拆成两条轨：UI 重组（不动后端语义）与能力增量（新功能另验收）
轨排期范围
UI 重组 · P0 第一周 Hero① 开启壳：唤醒→可选目标→可选激活键→进入听写；摄像头/SoftPad 旁链；合并状态徽章
UI 重组 · P0 第一周 Hero② 结束壳：复用 voice_end_runtime 自动/结束词/取消 + 时长/字数/静音倒计时展示
UI 重组 · P0 第一周 Hero③ 发送壳：显式化既有 send_mode（完成输入 / 发送 Enter）；删除 vp9HeroLive + homeAdvanced
UI 重组 · P1 第二周 设置页三 hero 绑 selectedMappingId；首页 howto 语音卡只读投影 activeSceneId；习惯切换节流刷新投影
能力增量 · 另排 P2+ 2s 撤销窗口 · 剪贴板发送 · 触发 SoftPad agent · 窗口智能推荐 — 各独立验收，不进「只重组 UI」承诺
配色:沿用 home-redesign-v19-m3core 的 M3 蓝主色 #00658F + 阶段色(蓝/橙/绿) · 落地时改用产品 --primary token · 1080px 基准
评估修正（2026-08-13）：Hero① 收窄因果链 · 编辑/使用绑定钉死 · UI 重组轨与能力增量轨拆分 · 首页只投影
