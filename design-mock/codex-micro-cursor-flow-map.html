Vibe Coding 完整流程 · 按键布局规划

不问「Micro 有哪些键」，而问：用户从打开 Cursor 到改完一版代码，手上要反复按什么。下表按会话时间线排；每一步写出 Soft Pad 该放的键，以及 Cursor 现在能不能接上。

用户在干什么（一条环，不是多条工作流）

  1. 人在微信 / 浏览器 → 要回到 Cursor 继续聊
  2. 对着输入框说一大段需求（或打字）
  3. 发出去，等 Agent 跑
  4. 跑偏了就停；停住等你就「继续」；聊乱了就新开一局
  5. 熟了以后才：切 Plan/Agent、接受 diff、开侧栏找文件
聚焦 → 说话 → 发送 →（继续 | 停 | 新局）→ 再说话
出厂必放（小白 4+聚焦） 第二周露出 更多 / 可绑 流程需要 · Soft Pad 还缺 不进 Pad · 口头指令 Cursor 不做

落到键盘上的分区（规划结论）

同一套 Soft Pad 拓扑（Codex Micro 底座）。Cursor 只换「出厂绑什么」，不另做第二块板。

本轮循环区（出厂高亮）

  • 大键 / 0：开麦 pushToTalk
  • Enter 位：发送 stopOrSend
  • 旁键：取消 cancel
  • 旁键：新局 newThread（建议长按防误触）
  • ENC：聚焦 Cursor summonCodex

模式列（+/· · 第二周）

  • + ：Plan
  • · ：Agent
  • 与官方 Micro「摇杆↑=Plan」同语义，位置改到模式列以免和循环键抢手

次环（默认可绑 · 不抢首屏）

  • 开聊天 quickChat · 命令菜单 · 搜文件
  • 侧栏 / 历史导航
  • 粘贴发送（标多步）· 跑我录的序列

流程缺口（要规划，尚未 Soft Pad）

  • 批准 diff → 补 acceptChanges* 进白名单
  • Fork（当前对话分叉）→ 有稳定和弦再补；勿用新局冒充
  • 「继续」→ 固定走口头指令，不进一键塞话
  • AG 六会话槽 / Fast / 旋钮模式 → 不做或仅灯近似
