摄像头能力清单 · 分类维度 · 新 IA 方案

摄像头页现有 10 个平铺子标签，把 46 项能力、4 类完全不同性质的设置混在同一层。用户的思路混乱不是能力太��，而是缺少一个能自己对上号的分类维度。本文档先列全清单，再给出 5 个可分类维度，最后用最合适的一个重构页面骨架。

46 项能力 10 个平铺子标签 5 个分类维度 7 个语义动作通道 推荐：维度 B · 感知层

0 · 先说结论：混乱的根因 不是能力多，是维度混了

把现有 10 个子标签按「它在回答什么问题」拆开，会发现它们根本不在同一个平面上。

10
平级子标签

「美颜」和「离席」并列，但一个是画面装饰、一个是自动化触发，用户的预期完全不同。

46
项能力散落

开关 21 个、下拉/单选 14 个、按钮 11 个，没有一项告诉你「我该在什么时候来开它」。

3
套设备被埋在「美颜」

分辨率、FPS、方向、抗闪烁在「美颜」页的折叠区里，和调色板混在一起。

2
个「摄像头」页面

settingsPanelCamera 与 settingsPanelCamera2 并存，能力边界互相覆盖。

关键错配：「校准」是一个前置条件，不是和「美颜」并列的同类项。用户必须先校准，视线类能力才准；但现在的结构把校准放在第 2 个标签，和「隐私」「久坐」平级，导致「为什么我的鼠标追踪不准」这类问题没有答案入口。

1.7 可绑定的语义动作（联动的「then」端）

所有 if-then 规则最终都指向同一套语义动作目录。摄像头可以绑定全部动作，但有两类高风险动作必须走二次确认，不能直执。

可直接执行（摄像头通道）

语音输入input.start / pause / cancel
输入收尾input.commit
本体onetone.pause / resume
界面overlay.toggle / status.read
应用app.open / app.shortcut
工作区workspace.applyLayout
Agent 调度focus / continue / interrupt / retry / respond
会话session.new / next · agent.status
选项choice.select

需二次确认（摄像头不可直执）

发送输入input.send
批准 Agentagent.approve

这两个虽然允许摄像头绑定，但触发后只会进入 Pending，必须由第二个通道（按键 / 语音）确认才真正执行。这是防误触的关键闸门，改版时必须保留可见的「需确认」标记。

顺带修复：「agent.reject」「agent.focus_waiting」在目录中但当前摄像头 UI 无清晰入口，建议在动作 Picker 中补齐并标注状态。

2 · 可以从哪些维度分类 5 个候选维度，各自解决不同问题

关键点：这 5 个维度不是互斥的，它们分别回答用户的 5 个不同问题。选哪个当主轴，取决于产品想让用户「先想什么」。

维度 A · 按技术模块分（当前隐含逻辑）现状

回答「这一项由哪段代码实现」——对开发有用，对用户无用。

采集层设备 / 分辨率 / FPS / 抗闪烁 算法层人脸 / 手势 / 视线 / 眨眼 规则层if-then 映射 渲染层美颜 / 面具 / 遮罩 策略层健康 / 隐私 / 静音
问题：用户不会按代码模块思考，这正是现在混乱的根源——它是开发者视角的分类泄漏到了用户界面。

维度 B · 按「感知层」分（推荐主轴）推荐

回答「摄像头在替我感知什么」——完全从用户的身体感知出发，天然自洽。

我在不在场离席 / 回席 / 旁人提醒 / 隐私卫士 / 范围指示 我在不在说话声音提示音 / 眨眼确认 / 点头确认 我在下指令五指 / OK / 握拳 / 挥手 / 摇头 / 故意眨眼 我在看哪视线校准 / 鼠标追踪 / 移窗 / 落点 我的状态久坐 / 20-20-20 / 坐姿 / 自动静音 我长什么样美颜 / 细调 / 隐私面具
优势：6 个桶互斥且穷尽，用户能一句话对上号（「我想让它知道我不在」→ 第 1 桶）。校准不再是独立标签，而自动落到「我在看哪」桶内，因为它服务的就是视线。所有设备参数移到左栏常驻或独立齿轮。

维度 C · 按「动作目标」分（联动匹配轴）

回答「我想让摄像头替我完成什么事」——如果产品想主打「自动化」叙事，这是最强的轴。

管我的语音暂停 / 恢复 / 取消 / 确认 管 Agent聚焦 / 继续 / 中断 / 重试 / 批准 管应用窗口打开应用 / 快捷键 / 移窗 / 恢复布局 管我的麦克风自动静音 / 开麦 管隐私遮罩 / 旁人提醒
优势：与语义动作目录（1.7）一一对应，改版后每个动作都能说清「我归哪一桶」。局限：画面观感类（美颜）和大部分参数无处安放，必须作为「不影响联动的独立区」存在，无法统一。

维度 D · 按「需不需要看屏幕」分（风险轴）

回答「这件事可不可逆 / 要不要我确认」——隐私敏感用户最在意。

无感自动自动静音 / 久坐 / 隐私卫士 / 久坐提醒 本机可逆暂停语音 / 美颜 / 鼠标追踪 需二次确认input.send / agent.approve 不可逆恢复工作区布局（会移动窗口）
优势：直接回答「敢不敢开」。局限：无法用来组织页面结构（同一项在不同上下文风险不同），只适合作为贯穿全局的视觉标记，例如给高风险动作加统一的「需确认」徽章。

维度 E · 按「什么时候需要设置」分（时机轴）

回答「我现在该不该动这个」——新手引导视角。

装好就能用装设备 / 分辨率 / 隐私默认值 第一次用要配眨眼基线适配 / 视线校准 / 屏幕布局 遇到问题才调抗闪烁 / 亮度对比度 / 灵敏度 / 手感 想换口味美颜 / 妆效 / 久坐间隔
优势：可以做成「一次性引导 + 折叠的高级项」，对新手极友好。局限：是时机不是内容分类，同一项会横跨多桶，不能作为主导航，但极适合做默认值和折叠策略。
组合建议：不要强行选一个。用 B（感知层）做主导航，用 C（动作目标）做联动选择器的分组，用 D（风险）做全局徽章，用 E（时机）决定默认折叠，设备参数收进 左栏常驻 + 齿轮。五轴各司其职，混乱自然消失。

3 · 用维度 B 重构的页面骨架 6 个感知桶 + 常驻联动列

结构核心：左栏设备常驻不再切标签，中栏按感知桶组织 if-then 规则，右栏固定「联动结果」，让用户始终能看见「我的动作会去哪」。

3.2 配套的结构修正

✅ 改版要点

  • 校准前置化：「我在看哪」桶顶部固定一条校准状态条，未校准时鼠标追踪/移窗显示为待校准并给一键校准入口。
  • 隐私面具归位：从美颜移到隐私同源区域，消除「装饰里藏安全功能」的错位。
  • 设备参数独立：分辨率/FPS/抗闪烁/亮度进左栏 ⚙，不再藏在美颜折叠区。
  • 动作目标分组：动作 Picker 按语音/Agent/窗口/麦克风/隐私分组，而不是平铺 25 个动作。
  • 风险徽章：input.send、agent.approve、恢复工作区布局统一加「需确认 / 不可逆」标记。
  • 合并双页面：camera 与 camera2 择一为准，避免两套摄像头设置并存。

⚠️ 需要你拍板的取舍

  • 「我长什么样」是否值得占一个桶？它是纯装饰、与自动化无关。可选择降级为左栏一个「画面观感」开关+面板，进一步压缩主导航。
  • 6 个桶是否仍偏多？若要更少，可把「我的状态」并入「我在不在场」，压到 5 桶。
  • 「布局」归属：它既非感知也非状态，纯粹是手动存档。可能应移出摄像头页到「工作区」独立页面。
