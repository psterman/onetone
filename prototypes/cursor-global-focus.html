OneTone · Cursor 全局对焦

说口令之后，怎么对到 Cursor 输入框

「全局对焦」不是一条魔法热键，而是两步硬动作： 先把 Cursor 窗体拉到前台，再点进右侧 Agent 输入框。 任一步失败就停（fail-closed），避免字打进编辑器或 Git 提交框。

先分清两层

用户说的「切到 Cursor」经常混了窗体与输入框。产品与实现必须拆开写。

Layer A · 窗体

找到 Cursor.exe 窗口并置前

入口：ensure_app_window → focus_window(hwnd)。 Profile：cursor-chat，进程名 Cursor.exe。 没有窗则试冷启动 %LOCALAPPDATA%\Programs\Cursor\Cursor.exe。

Layer B · 输入框

点右侧锚点 + UIA 验焦

入口：aim_input_focus → focus_composer_for_send。 锚点 (0.84, 0.91)（窗客户区相对坐标，偏右下 Agent）。 不发 Ctrl+I（编辑器焦点下会变行内编辑）。

端到端流水线

点步骤展开实现要点。一词注入（如「么么哒」）在 wrong_fg 之前走这条链。

01

口令命中一词注入 peer

ASR 听到唤醒词 → find_prompt_inject_peer_for_phrase → 取 peer 的 Text + Enter。

已落地 peer 自带 voiceOverride.wakePhrases[0]； 不依赖全局 voiceEnd.intent。 注入路径不经过 wrong_fg 拒绝（aim 自己负责切窗）。
02

共享对准入口

dispatch_prompt_inject → aim_input_focus(app, "cursor-chat", strategy)。

已落地 策略 UI：「先对准 / 直接填 / 已对准才填」。 Phase0 非 none 全部落到同一套 focus_composer_for_send。 Voice / Soft Pad / Keys 注入共用，禁止各写一套点屏逻辑。
03

窗体层：藏 OneTone → 置前 Cursor

MainWindowHideGuard（设置页打开时可能跳过）→ 找/启 Cursor → focus_window。

注意 Soft Pad / 设置抽屉仍可能报 FG=self；发送路径以「输入框是否有键盘焦点」为准，不再仅凭 FG=self 失败。 「不在目标窗时自动切过去」主要服务听写 wrong_fg；一词注入已绕过该闸。
04

输入框层：相对点击 + UIA

客户区相对点击 (0.84, 0.91) → UIA 找 Edit/Document → 要求键盘焦点；SCM「Message…commit」降权。

已落地 日志：cursor-send-oplog.jsonl（focus_start → click_post → uia_* → focus_result）。 失败 → VOICE_PROMPT_AIM_FAILED，不注入。 前提：Cursor 右侧 Agent/Chat 侧栏最好已打开；侧栏关闭时锚点可能落空。
05

对准成功才 Text → Enter

run_action_sequence([Text(prompt), Key(Enter)])。

已落地 Soft Pad「口头指令」与一词注入同语义（Text+Enter + 同一 aim）。 成功事件带 route: peer | intent。

可落地交互说明

给产品 / 测试 / 实现共用的验收表。

场景期望失败时
前台已是 Cursor，Agent 输入框已亮 口令 → 直接写入并回车 —
前台是别的 App / OneTone 设置页 自动置前 Cursor → 点输入框 → 写入 toast「对准输入框失败」，不打字
Cursor 开着但焦点在代码编辑器 相对点击右侧 → UIA 确认后再写 同上；勿用 Ctrl+I
Git 提交框 / SCM Message 可见 UIA 降权，不把它当 Agent 框 对准失败，不提交脏 commit
策略「直接填入」 跳过 aim，假定用户已点进框 误注入由用户自担
策略「只在已对准时填」 探测无焦点则取消 不主动点屏
