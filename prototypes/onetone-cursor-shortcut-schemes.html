Cursor 快捷键 · 怎么分才科学

当前把「做什么 / 怎么触发 / 去哪改」拧成五颗标签，所以 plan（Cursor 模式键）和 status（斜杠插入）挤进同一桶，而 app.shortcut 又刷出一堆「应用快捷键」。下面用同一批 Cursor 命令对比四套切法。

现状诊断
  • 轴混用：native/agent/view/click/shortcut 一半看 action 语义，一半看通道组合。
  • Cursor 真快捷键没独立身份：有默认和弦的槽（终端 / 命令面板 / Plan / 切换助手）与泛型 app.shortcut 混称「快捷键」。
  • 标签过多：五类 ActionCategory × 五颗粒 kind × 通道灯 = 用户记不住。
  • 匹配过宽：仅按键的同名行、Soft Pad 种子、Beginner 布局一起进投影再靠噪声过滤补救。

方案 · 现在

五颗粒混轴

通道图标是对的；Agent 内再切 native/agent/view/click/shortcut 不科学——同一命令换通道组合就会换桶。

判定

先看 soft: → native；仅按键 → shortcut；再 insertOnly → view；再 Agent id → agent；再 Pad → click。

失败点

plan 在 Cursor 是模式热键（非斜杠），却因「仅按键」成 shortcut，有口令的 status 又成 view——用户无法建立「这是 Cursor 快捷键」心智。

不推荐保留为最终心智；通道灯可留，五颗粒应拆轴。

方案 A

按「改哪儿」分桶

用户问题本质是调整路径。有口令的进「说法」；无口令但有按键的进「按键」；其余进 Pad/手势。app.shortcut 不进习惯列表。

规则

hasOral → 说法；else hasKey → 按键；else Pad/手势。通道灯仍正交显示全部绑定。

代价

「继续」有口令也有键，进说法桶——Cursor 键身份被淹没；适合「我要改调用方式」场景，不适合教「哪些是 Cursor 自带快捷键」。

适合 CTA / 深链，不适合当 Cursor 能力教材。

方案 B · 推荐

按 Cursor 产品角色

只回答「这能力在 Cursor 里是什么」。通道仍用图标；不再用五颗粒。Cursor 快捷键 = 命名槽 ∩（有默认和弦 或 已绑定键），与泛型 app.shortcut 硬切开。

Cursor 键白名单

来自 CURSOR_DEFAULT_KEY_BY_SLOT / VS Code 系共享表：openTerminal、commandPalette、plan、switchAgent、quickSearch、undo、toggleSidebar… 副行主显和弦。

斜杠 vs 模式键

真正 insertOnly 且无 Cursor 专用 chord override → 斜杠；Cursor 把 plan/switchAgent 标成模式热键（见 Soft Pad isSoftPadInsertOnlySlot）→ 进 Cursor 键，不进斜杠。

对话控制

continueReply / 中断 / 新建 等 Agent 推进类，不叫快捷键。

剔除

app.shortcut、cursorBeginner*、无说法的 custom Soft Pad 种子 → 不进习惯；去 Keys / Soft Pad 管。

方案 B′ · 可落地细分

只切「Cursor 快捷键」

四桶顶层不动。白名单变长时，仅在键桶内用子标题（不是新手风琴）分成两类——用户仍认「这是 Cursor 键」，再认「模式还是壳」。

值得切 · Agent 模式键

Cursor 特有 / 改 Composer·Agent 状态：plan、switchAgent、quickChat（Ctrl+I）。判定：在 CURSOR_DEFAULT_KEY_BY_SLOT 里有相对 VS Code 共享表的覆盖，或 Soft Pad 明示非 insertOnly。

值得切 · 编辑器壳

VS Code 系共用壳：openTerminal、commandPalette、quickSearch、toggleSidebar、undo、nav*、openSettings… 和弦来自 VSCODE_EDITOR_KEY_BY_SLOT。

不值得切

对话控制再切推进/打断/会话 → 每桶 1～2 条，纯噪声。斜杠条目少，扁着放。Soft Pad 不拆「口令 / 点击」——那是通道，不是角色（通道灯已表达）。

触发条件

键桶 ≤4 条 → 用 B（无子标题）。≥5 或同时出现模式键+壳键 → 开 B′ 子标题。实现上就是 cursorKeyFamily: 'agentMode' | 'editorShell'，不必新 Category。

推荐：落地 B；键桶变长时自动升 B′。不要把对话/斜杠/Pad 再切碎。

方案 C

双轴极简

手风琴只留大类（输入 / Agent / …）。Agent 内不再分子标题；每行最多一枚徽章：Cursor 键 · Agent · Soft Pad · 斜杠。排序：Cursor 键优先，再 Agent，再 Soft Pad。

规则

白名单有默认和弦 → Cursor 键；insertOnly 且非 Cursor 模式键 → 斜杠；soft: → Soft Pad；其余 Agent。

代价

长列表时「Cursor 键」不成块，扫视线靠徽章颜色；实现最轻（改 kind 映射即可）。

可作 B 的轻量过渡：先换徽章语义，再加分组。

方案 D

白名单置顶 + 噪声折叠

习惯页第一眼就是 Cursor 真快捷键（和弦作主文案）。可说法的排第二。app.shortcut 合成一行「自定义快捷键 · N」深链 Keys，彻底消灭刷屏。

规则

同 B 的白名单；列表顺序强制 Cursor 键 → 可说法 → 折叠桶。

代价

习惯页更像「快捷键速查」；若产品定位是「多通道调用」，可能抢 Keys 页的戏。

若目标是「一眼认出 Cursor 键」选 D；若目标是「习惯=调用方式」选 B。
