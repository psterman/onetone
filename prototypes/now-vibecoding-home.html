操作去哪了：不在这页

关键判断：vibe coding 时你不会去点 UI。 所以首页上的按钮都是兜底——给「我现在不方便说话」用的。

vibe coding 循环里，操作应该在哪

1说需求🎤 语音
→
2等它跑不用管
→
3批准 / 拒绝🎤 说，或手势
→
4打断🎤 「停」或摇头
→
5看结果👀 或 🎤 问
五步里有四步不碰 UI。 所以首页那三个按钮（同意 / 拒绝 / 停一下）不是主路径，是给手不方便时的备选。

这也解释了为什么按钮要写得这么朴素——它不需要好看，需要一秒钟认出来。

每种操作该走的通道

操作首选备选为什么这么排
同意 / 拒绝🎤 说「同意」Ctrl+J / Ctrl+K 你眼睛在代码上，嘴比手快。这两个键要能和打字区分开
打断 agent🎤 说「停」或摇头— 打断需要最快的反应。摇头是唯一不占用键盘的方式
切情景自动（不用做）Ctrl+Space 正常情况不需要手动切。手动切 = 自动切换没跟上
看它在干什么🎤 问点「查看进度」 问比点快，而且不打断你的视线
改习惯设置页— 这是低频配置，不该出现在 vibe coding 时刻
一个现实约束：你现在的主通道是 RAlt。 如果「同意」也用 RAlt 系，你无法在打字时无误触。

Ctrl+J / Ctrl+K 在编辑器里都是常用键（VS Code 里 Ctrl+K 是 chord 前缀）。 需要挑真正不冲突的键——或者干脆只留语音。

这版需要什么数据

先说清楚哪些现在就有，哪些必须新建。不编造「它在等你」这种句子。

必须新建的数据

首页元素状态为什么现在做不到
「已经等了你 2 分 14 秒」缺 Pending 有 TTL，但没记录创建时间戳。需要加 created_at_ms
「这 2 分钟没弹窗」缺 完全没有「被抑制」的记录类型。需要新增 kind: "suppressed"
「等你停下才叫你」缺 需要判断「你在不在打字」——InputObs 有原始流，但没聚合成专注度
「在你的 Cursor 习惯里」有 但习惯名是技术串，需要 displayName 字段
最关键的一条是「被抑制」记录。
AttentionState::Complete 的 TTL 是 4 秒 （agent_attention/model.rs:10）——AI 做完后 4 秒状态就消失了。

这意味着系统现在根本不知道「我本来可以叫你，但我没叫」。

而这恰恰是 OneTone 跟一个只会弹窗的助手唯一的区别。 建议优先做这个：给 AttentionStore 加一个「延后通知」队列， 记录本该通知但选择了不通知的事件，事后在首页汇总。
为什么「克制」比「做了什么」更值得放首页：

「今天帮你挡了 5 次通知」——用户已经有感知了（他没被打断）。
「今天调用了 23 次 API」——用户不知道该高兴还是担心。

克制是可以炫耀的，功能调用不是。
