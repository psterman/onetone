A 和 B 下沉去哪

不删除，换位置。它们对高级用户依然有价值，只是不该占据第一屏。

A「我看到的你」→ 诊断 设置 / 隐私与诊断 高级
设置 ├── 隐私与权限 │ 摄像头 · 麦克风 · 键盘 开关 │ 画面是否只在本机处理 │ └── 诊断 ← A 搬这里 ├── 它现在怎么理解你 │ 正在写代码 ← Cursor在前台 + 项目有改动 │ AI 正在等你 ← Codex 请求批准 │ 你在不在 ← 摄像头未接入，显示"不知道" │ ├── 它靠什么知道 │ 👁 摄像头 在不在 / 看哪块屏 只在本机处理 │ 🎤 麦克风 在不在说话 只在主动触发时录音 │ 🖥 窗口 前台是谁 只读标题 │ ⌨️ 键鼠 最近有无敲键盘 只统计节奏 │ └── 为什么它这样判断 ← B 的因果链也在这

改名是关键：它现在怎么理解你 比 我看到的你 少一分窥视感， 多一分向用户求助的意味——「我判断错了？告诉我」。这把它从「监控面板」变成「设置项」。

B「今天为你做了什么」→ 回顾 独立页 / 或未来的 Memory 低频
回顾（独立页） ├── 今天 │ 12 次主动帮助 │ 16:40 你摇了摇头 → AI 停下来了 │ 15:07 你回到座位 → 恢复工作现场 │ 14:32 你离开了 → 屏幕挡住了 │ ├── 本周 │ 周报 / 趋势 / 哪些帮助真的有用 │ └── 未来：OneTone Memory

这是成果中心，它的读者是「想回顾的我」，不是「正在工作时的我」。 放首页会让人分心——工作的人不想看昨天的统计。

分层关系

每层只回答一个问题，不要混：
现在（首页） 现在是什么状态？→ Resolver 输出 回顾 我今天得到了什么？→ ActionHistory 设置 · 隐私与权限 它在用我的什么？→ 开关 设置 · 诊断 它凭什么这么说？→ Context 明细 情景管理 我想要什么状态？→ mappings
