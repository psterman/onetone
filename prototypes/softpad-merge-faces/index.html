Soft Pad · 合并方案讲解稿

虚拟键盘 + 灯效浮窗
不是两个产品，是同一块板子的不同旋钮

给产品/设计/测试看的完整说明：现在拆成两间「房间」各自藏了什么、为什么不合理、合并后每一项去哪、合并后界面怎么操作。

生活类比：Soft Pad 就像桌上那块「给 Agent 用的遥控板」。 「虚拟键盘」是在改按键和什么时候亮出来；「灯效与浮窗」是在改灯怎么闪、迷你条长什么样。 现在却要你先选进 A 房间还是 B 房间——其实板子就一块，旋钮应在同一面板上。

01

现在有什么（完整清单）

先把两间房间里的东西摊开。合并不是「删一半」，是「搬家」——每样东西都要有着落。

现状结构 顶上先选：「虚拟键盘」或「灯效与浮窗」→ 再进各自内部的小标签。像进了两个 App。
房间 A

虚拟键盘

  • 显示 appear
    • 什么时候出现（跟随应用 / 置顶 / 迷你条 / 不显示）
    • 出现场景示意（桌面预览）
    • 外观皮肤（选皮肤 → 左预览变真皮肤）
    • Cursor 聆听口令（可选）
  • 键位 keys
    • 左侧：键盘实物预览（点键帽）
    • 右侧：命令库（我的常见 / 按场景 / 本应用）
    • 绑定：键帽 ←→ 动作（继续、批准、听写…）
  • 用途 purpose
    • Soft Pad 映射（与数字键盘同一键位）
    • 数字键占用 / 临时切换
    • 方向栏（导航键）演示与开关
房间 B

灯效与浮窗

  • 灯效匹配 match
    • 当前 Agent 就绪（Pad 开关、接入状态）
    • 氛围灯（盘边呼吸 / 脉冲 / 静态）子 tab
    • 按键灯（键帽高亮、配色模板）子 tab
  • 显示数据 data
    • 状态栏显示：账号 / 额度 / 重置
    • Cursor 活动 / API 额度候补
    • 跳去迷你栏的入口
  • 迷你栏 mini
    • 谁在忙（跨应用指示）
    • 听你说话（语音相关指示）
    • 快捷钮
    • 浮窗形态（大键盘 / 迷你条 / 不浮出）
共用、不在房间里的东西（合并后也不动） 顶栏品牌「虚拟键盘」、开关状态、绑定应用（Codex/Claude…）、测试前台、编辑键位按钮、设置中预览提示条。
02

为什么要合（合理性）

不是为了「标签变少好看」，而是现在的切法会让小白迷路，也和真实使用方式打架。

1

对象是同一个

灯打在键盘边上，迷你栏是键盘的缩小形态。拆成两个入口，像「车灯设置」和「方向盘设置」要进两个 App。

2

任务不需要先选房间

用户心里是：「改 Codex 这块板」。不会先想「我现在算键盘用户还是灯效用户」。

3

内容有重叠

「显示」管何时浮出；「迷你栏·浮窗形态」也管大/小/藏。分两房后，同类问题要跑两趟。

4

绑定应用是共享的

键位、灯效、迷你栏都跟着「绑定 · Codex」。顶上再切 face，等于重复声明「这是哪个 App」。

5

预览本应连着改

左边预览是同一块板：改键、改灯、改迷你条都应打在同一预览上，而不是换 face 换宿主。

6

不是删功能

合并 = 取消「先选房间」。房间 B 的每一项都搬进同一排标签，能力完整保留。

一句话结论 Soft Pad 页只应回答：「这块板怎么显示、怎么按、干什么用、怎么发光、缩小成什么样」——五个问题，一排标签，不必两张脸。
03

合到哪里（搬家表）

左边「原来在哪」→ 右边「合并后去哪」。方便对照验收：少一项都不行。

原来 具体内容 合并后 说明
A 显示 出现时机、场景、皮肤、聆听 显示 原样保留
A 键位 键帽绑定命令 键位 原样保留（主入口）
A 用途 映射 / 占用 / 方向栏 用途 原样保留
B 灯效匹配 就绪、氛围灯、按键灯 灯效 整包搬入；子 tab 仍分氛围/按键
B 显示数据 账号/额度/重置、Cursor 用量 迷你栏 首段 不再单独占一顶栏；和浮窗「看见什么」放一起
B 迷你栏 谁在忙 / 听你说话 / 快捷钮 / 形态 迷你栏 主体 原样保留在「迷你栏」下半
A|B 顶部分区 虚拟键盘 | 灯效与浮窗 删除 唯一砍掉的是「选房间」这一层
为什么「显示数据」塞进迷你栏，而不是第六个 tab？ 它管的是「条上显示什么数」，和迷你栏/浮窗强相关；单独占 tab 会让顶栏变成 6 个，小白更难扫。显示数据里本来就有「去迷你栏」的跳转——说明两者本就是一对。

05

用户怎么用（合并后路径）

用三件最常见的事，对比「现在」和「合并后」要走几步。

A

我想给 Codex 改「继续」键

现在：进虚拟键盘房间 → 键位 → 点键选命令。
合并后：打开 Soft Pad → 键位 → 同样操作。（少一步选房间）

B

我想把盘边灯改成呼吸

现在：先切到「灯效与浮窗」→ 灯效匹配 → 氛围灯。
合并后：打开 Soft Pad → 灯效 → 氛围灯。（仍是配灯，但不再换「脸」）

C

我想看额度，并把浮窗改成细条

现在：灯效房 → 显示数据看额度 → 再切迷你栏改形态（两次顶栏）。
合并后：迷你栏一页里：上面数据，下面形态。（相关能力放一起）

06

小白问答

合并方案最容易被误解的几点，先答清楚。

是不是把灯效功能删掉了？
没有。灯效、迷你栏、显示数据全都还在，只是从「第二张脸」搬进同一排标签。删掉的只有「先选虚拟键盘还是灯效」这一层门。
五个标签会不会太多？
比「2 个大门 + 门内再 3 个」更少层级。扫一眼能看见全部能力；以前灯效藏在另一扇门后，小白常常根本不知道有灯可配。
「显示」和「迷你栏」会不会重复？
有分工：显示 = 何时出现、皮肤；迷你栏 = 缩小后的形态与条上信息。合并后反而方便对照，避免两房各改各的。
为什么不做成「高级设置」折叠？
灯效和迷你栏是日常能力（看谁在忙、盘边状态），不是调试项。藏进高级会再次制造「第二房间」。
和按键页 / 语音页有什么关系？
无关。这次只整理 Soft Pad 自己页里的两张脸。按键流水线、语音听写仍是各自的页面。
开发上难不难？
主要是路由：去掉 face 切换，把 agent 面板按 tab 画进同一个右侧宿主机；预览共用一个宿主。功能函数大多可复用，属于搬家不是重写。
