仍需解决的：名称投影

唯一还做不到位的是情景名「Cursor 开发」。
habit_profile.rs 的 habitDisplayName() 返回 m.label， 而 label 默认是 「AutoTrigger → xxx」 这种技术串（config-persist.js:993）。

需要新增一个字段，比如 MappingEntry.displayName: Option<String>， 由用户在「调整习惯」时自己起名：「Cursor 开发」「VS Code 开发」「PS 设计」。

在这之前，首页只能显示 label 原样——那就等于把技术串暴露给用户。 所以名称投影是首页能上线的硬前置。

摄像头那两行为什么独立显示

因为摄像头动作不走统一路由。
其他动作是 targetActions（语义动作，有 label_zh，走 route_semantic_action）； 摄像头动作是 presenceActions 里的本地 token（privacyScreen / pauseVoice / …）， 由 camera-presence-actions.js 自己执行。

这是我在前面几轮核验时发现的两套并行动作系统。 UI 上分开显示是诚实的做法——强行合并会让用户以为它们是同一种东西。

保留下来的，全部是实时数据

判断标准很简单：这条信息能不能在不重启的情况下变。
  • 能变 → 保留（绑定会改、次数会涨、mode 会切）
  • 不能变 → 就是硬编码，删
按这个标准，「编程语音快捷键」在所有场景下都长得一模一样——它是文案，不是数据。
顺带解决的一个大问题：数据驱动之后，assists 那套通用标签的问题会自己浮出来。

用户会看到「回到当前 Agent / 开始听写 / 中断」这些真实动作，而不是「保持专注」这种空泛承诺。 这时候 assists 就不再是首页的主角了——它变成了一层「我要不要开这个动作」的开关， 存中文 label 的问题也就自然解决了（因为不再需要翻译，它就是给人看的）。
