# 折腾 DSH 一个月，插件从 30 个删到只剩 12 个（附安装命令和避坑清单）

先说结论：**DSH 的插件，装得多不等于用得好。** 我从一个下午装满几十个、界面挤爆、后台红字刷屏的状态，退回 12 个能天天用的，这条路比大多数人想的绕。

先交代身份，免得你觉得我在硬推：**DSH Market（插件市场）是我在维护的**，下面第一节会把它当作"找插件的入口"来推荐。你完全可以当广告跳过，直接翻第二节的清单——那 12 个里只有 1 个是我的，剩下 11 个都是社区作者的。

---

## 一、先把「找插件的入口」准备好

新手的第一个卡点往往不是插件不好用，是**根本不知道从哪找**。DSH 现在有两条路：

**① 官方的插件市场 bundle（还在实验阶段）**

官方已经提供了 `@deepseek-ai/dsh-experimental-plugin-market-bundle`，版本号还是 `rc`（我这台是 `0.2.2-rc.3`），入口在设置里。官方自己的东西，兼容性最稳，缺点是收录范围还在扩。

**② DSH Market（社区的，我维护的）**

在设置页里逛、搜、按分类筛、点一下装好。当前线上收录 **10936 条**，多数走 npm tarball，秒级装完，还能一键更新、导出配置备份。选它纯粹是因为全——不是要你非装不可。

不管走哪条，**先搞清一件事：命令里的 `--profile` 要跟你实际在用的那一端对齐**。

```bash
# 纯网页版（dsh web）
dsh plugin --profile web add <包名>

# 桌面客户端，把 web 换成 desktop
dsh plugin --profile desktop add <包名>
```

写 `--profile desktop` 但你跑的是网页版，就会装到一个你根本没在跑的环境里——插件"装了却没反应"，十次里有八次是这个原因。**用市场页面点安装的话，它会自己判断，不用你操心这个参数。**

> 桌面端还有个小坑：它自带的 dsh 版本可能比 npm 上的旧（我见过 #139 这类问题），市场装不上时先确认版本够新。

## 二、12 个插件，按「解决什么问题」分

装之前先问自己一句：**我缺的是哪一环？** 下面按用途分组，同一类只挑一个。

### 1. 让它先跑起来

**dsh-free-model** — 把外部账号接成模型

```bash
dsh plugin --profile web add dsh-free-model
```

> 这是 `dsh-our-free-model` 的精简 fork，只保留一条车道：**15 个账号渠道 + 数据看板 + 运行日志 + 本地网关**，上游的匿名免费车道被作者主动移除了。所以别把它当成"免费通道"——它是"把你已有的账号接进来"的通道。
>
> 想要上游完整版（走 GitHub 安装）：
>
> ```bash
> dsh plugin --profile web add github:Ebony-Vinyl/dsh-our-free-model
> ```
>
> 装完进设置页逐个授权。我这台当前能看到 **11 条免费模型入口**（`mimo-v2.6-flash-free`、`deepseek-v4.1-flash-free`、`glm-5.3-flash-free` 等），这个列表跟着上游变，别把它当承诺。
>
> ⚠️ 顺带一提：网上流传的"最新版藏了入口、必须回退 3.1.0 旧版"——**现在 3.1.0 就是 npm 上的最新版**（11-11 发的）。省 Token 这类功能被移走，是 fork 的设计取舍，不是被谁藏起来。回退也回不来。

**@deepseek-ai/dsh-experimental-plugin-market-bundle** — 官方实验版市场，见上一节

### 2. 干活的界面

**dsh-better-sidebar** — 给聊天框配一张办公桌

```bash
dsh plugin --profile web add dsh-better-sidebar
```

原生 DSH 只有中间一个对话框，AI 生成的文件打不开、本地目录也看不见。这个补上右侧工作台：文件渲染与编辑、终端、Git、子代理都在里面，三方插件还能注册新 Tab。**这是我留着时间最长的一个**（5142 star，装机量 33 万）。

**@wszhoho/dsh-file-attachment** — 传文件，别再复制粘贴

```bash
dsh plugin --profile web add @wszhoho/dsh-file-attachment
```

拖拽、`Ctrl+V` 粘贴、📎 按钮上传都支持，文件统一落盘到 `.dsh-file-attachment`，再用 **`@绝对路径`** 引用发出去。纯文本模型也能正常读——图片则会自动调用你配置的 VLM 生成中文描述回填草稿。

> 📎 一个常见误会：输入框里打 `@` 弹出的文件联想，是 **DSH 自带**的能力，不是这个插件的功能。想用自动补全，装了它也不用额外做什么；想发指定文件，用 `@绝对路径` 最稳。

**billion-context** — 长会话的上下文压缩

```bash
dsh plugin --profile web add billion-context
```

聊几周之后历史越滚越长，token 越烧越贵、模型还容易忘掉前面的约束。它在后台压缩会话，官方口径是 100K 上下文够用、token 省 5 倍。

**但摘要不等于原文**：数字、格式、交付标准这类不能改的要求，单独留一份档，别只指望自动压缩后的记忆。

### 3. 让它能看、能搜、能动手

**dsh-vision-router** — 给纯文本模型装眼睛

```bash
dsh plugin --profile web add dsh-vision-router
```

装完重启，模型列表里会出现视觉路由选项。对话里带图时自动调度视觉通道做 OCR 和版面解析——以后发报错截图过去，它能直接读。

> ⚠️ **它的 README 自带警告，默认是会把数据发出去的**：用了云端视觉模型时，图片、裁剪块、视觉提示词和请求元信息都会离开你的机器；新装还默认开着匿名 OVHcloud 视觉兜底。**"免费""免 key"不等于离线**——机密或合规材料记得切严格本地模式，或者干脆关掉兜底。

**@liustack/modsearch** — 联网搜索

```bash
dsh plugin --profile web add @liustack/modsearch
```

网页搜索、X 搜索、正文抓取，结果是带引用的结构化 JSON。默认走 Firecrawl 无 key 通道（每月 1000 次免费额度），不用注册不用填 API Key，失败自动切下一个引擎。

**dsh-builtin-browser** — 让它真的去点网页

```bash
dsh plugin --profile web add dsh-builtin-browser
```

搜索拿得到的就别启动浏览器；真需要翻页、点击、填表再让它上。它开的是真实浏览器窗口，你能全程看着，必要时随时接管。

> 实操建议：给它单独准备一个浏览器配置文件，登录态和日常浏览器分开——**便利可以要，权限别一次给满**。

### 4. 钱和安全感

**dsh-whale-widget** — 余额挂件

```bash
dsh plugin --profile web add dsh-whale-widget
```

右下角常驻一只小鲸鱼：API 余额、今日已用、每轮对话消耗（含峰谷价）。余额预警和预算提示的文案、角色、形象都能自己改。内置 30+ 厂商模板（OpenAI / OpenRouter / Kimi / 硅基流动 / MiniMax 等），数据全在本机，无遥测。

> **要分清两件事**：看得见消耗 ≠ 能自动限制消耗。余额展示、低余额提醒、单日预算上限、到顶自动停，是四个不同层次的能力。它支持哪些，看它的说明，别默认"装了挂件就等于给后台任务上了刹车"。

**dsh-rewind-plugin** — 后悔药

```bash
dsh plugin --profile web add dsh-rewind-plugin
```

改方案改到第五轮，发现第三轮最好——它能就地回退到任意更早的那条消息，目标消息自动填回输入框，还能**一并还原工作区里被改过的文件**。会话日志只追加回退标记，不删任何东西。

> 回退对话 ≠ 备份文件。它还原的是它追踪到的那部分写操作，重要项目照样该有 git。

**dsh-pocket** — 人在外面也能用

```bash
dsh plugin --profile web add dsh-pocket
```

扫码就能用局域网或公网（cloudflared 隧道）访问电脑上的 DSH，手机端有适配布局。

> 我这边遇到过竖屏白屏的情况，横屏能规避；如果你也遇到，可以先横屏，再逐个停用最近装的界面插件定位。**这是我自己的现象，不一定人人都有。**

**@xmanrui/dsh-im** — 把入口搬进聊天软件

```bash
dsh plugin --profile web add @xmanrui/dsh-im
```

扫码接入后，你人不在电脑前也能问它。支持飞书、微信、钉钉、企业微信、QQ、Telegram、Discord、Slack、WhatsApp 共 9 种渠道。

> ⚠️ **务必用独立小号。** 高频自动化响应很容易触发平台风控，轻则限制发言，重则封号，主力私人号别挂。

## 三、避坑指南：这 7 个雷我替你踩了

### 1. 同类插件只留一个

侧边栏装三个、浏览器控制再来一套，听着装备拉满，出问题时你根本不知道是谁接管的哪个按钮。挑的时候看这四条：最近还在维护吗？兼容版本写清楚了吗？报错后有解决方案吗？权限说明清不清楚？**Star 数可以参考，别当唯一标准。**

### 2. 更新之前先给自己留退路

```bash
# 1. 备份工作区和配置
# 2. 记下当前可用的主程序 + 插件版本
# 3. 分批更新，别一口气全点
# 4. 更新完先测常用任务
```

官方底层一升级，第三方插件大面积飘红是家常便饭。不然出问题时你面对的不是"某个插件坏了"，而是"刚才一起更新的十几个东西，到底哪个坏了"。

### 3. 卸载插件 ≠ 可以随便删配置

有些插件停用或卸载后就恢复了；有些问题还得查残留配置和依赖关系。但别一报错就对 AI 说"把相关文件都删干净"——**"相关"你没说清，它未必理解得比你准**。

更稳的问法：

> 先定位这个插件关联的配置和目录，逐个解释用途，列出建议清理的清单，备份后再操作，不要动其他插件。

### 4. 别为了省一次确认，把权限全放开

安装确认、命令确认、文件修改确认，偶尔确实烦。但**免确认应该只免掉重复的那部分**：跑终端命令、读敏感目录、改配置、对外发内容，这几类该看还是得看。

### 5. 别信"一键全自动"

再神的插件也是工具。复杂任务盯着点，余额挂件 + 预算熔断双保险，是底线配置。

### 6. 社交入口单独管理

除了用小号，顺便把这三件事定下来：**谁能向它发指令、允许读哪些目录、哪些操作必须确认**。接通了不等于配置完成。

### 7. 装插件前先看它要什么权限

这个生态现在有一万多个插件，钓鱼和跑飞都有。装之前看一眼它要 `fs-write` 还是 `shell`、数据往哪儿发。**一个正常的工作台插件要 shell 权限，值得停下来想一想。**

## 四、新手按这个顺序来，别一次装完

如果你刚开始用，**别照着这篇一次装完**。我的顺序：

1. **先把一个模型接通** —— 能聊天、能读文件、能完成任务，这条链路跑通再说
2. **再配好插件入口** —— 官方市场或 DSH Market，二选一
3. **经常传文件** → 补 `dsh-file-attachment`
4. **经常处理项目** → 补 `dsh-better-sidebar`
5. **长任务多** → 补 `billion-context`
6. **要截图、要查资料** → 补 `dsh-vision-router`、`@liustack/modsearch`
7. **最后按需** → 浏览器控制、余额挂件、手机访问、IM 接入

**预算这件事，从第一天就该心里有数**，不是出问题才想起来。

## 写在最后

我喜欢 DSH 这类工具，不是因为它能把界面堆得多热闹，而是你可以按自己的需求，一块一块搭出顺手的工作环境。**插件多是选择，装得克制才是本事。**

真正好用的插件，最后往往会让你忘记它的存在——你不再研究它有多少功能，只会在干活时顺手用上。

至于装完以后，每天还得花半小时伺候它的——先别急着叫它生产力，也可能是你给自己找了个电子祖宗。
