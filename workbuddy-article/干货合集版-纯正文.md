# WorkBuddy 进阶用法：别只拿它当搜索框

WorkBuddy 是常驻任务栏的桌面客户端，跟网页 AI 最大的区别是**它能交付成品文件**——文档、表格、PPT、网页，甚至小程序，而且能连着跑一整条流程。

混元 Hy4 已接入，限免到 11 月 15 日。下面按「你大概在做什么 → 换个做法」过一遍，能力和坑都算上。

---

## 一、提问：四段式，第 4 条才是分水岭

初级用法是"帮我分析一下销售数据"，然后等它想半天。

改成这样：

1. **你有什么**（给事实）—— 近期销售数据截图、业务报表、竞品情况，别让它猜
2. **你希望什么**（给判断标准）—— 统计口径是什么？目标是提销量、提曝光，还是调策略
3. **你要什么**（给约束）—— 文风、长度、使用场景（汇报/存档/教学/复盘/周报/求职）、格式（Markdown 报告 / 带公式的 Excel / HTML 交互页）
4. **你要的结果**（验收标准）—— 按利润率降序排前三、高亮亏损 SKU、给三条能落地的建议

**第 4 条是分水岭。** 没有它，你拿到的是"一篇看起来很像报告的东西"；有了它，一眼就能看出它有没有照做。

懒得一次写完也行：先把行业、城市、销售计划、竞品动态这些背景聊清楚，再让它出综合报告，接着针对报告里你关心的部分继续追问。

### 三个让返工少一半的习惯

**长需求末尾留一句余地**：

> 请先给出第一版基础结构，待我确认后再细化修改。

**流水线提示词必加异常兜底**：

> 若遇到数据缺失或读取失败，请立即停止并通知我，切勿使用预估值编造数据继续往下跑！

**一次只改一个地方，说具体位置和属性** —— "把主标题字号改小一档、颜色换深蓝"，而不是"改得高级一点"。

## 二、资料库：它是上下文，不是网盘

初级用法是"WorkBuddy 生成的内容保存到本地改"。改成往资料库里放。

资料库内置**腾讯文档、乐享知识库、ima 知识库**（ima 下期单独聊，非常赞），另外官方还有个 **Buddy One** 套件，把 WorkBuddy、腾讯文档、腾讯会议、腾讯网盘、腾讯 ima 关联成一套账号，支持跨产品检索——散在文档里的企业资料、ima 里的政策库、会议里确认过的结论，可以在同一个任务里一起调用。

**产物去处**：资料库、腾讯文档、ima 知识库、乐享知识库，也能用链接 / 微信 / 企业微信三种方式分享。

**资料库的分工挺讲究**：**MD 定内容、CSV 定数据、HTML 定表达**，三者互相引用。要沉淀的是判断标准，不是文件。

**这里有个必须知道的机制**：它改 MD 文档**不覆盖原文，以"待确认"状态给你看**，你点了接受才写进去，随时能退回。所以让它"自动生成一页动画教学"这种说法不准确——真实能做到的是给你一份可交互的 HTML 教学页，改动留在结果区里回溯，接着追问继续迭代。

**连接器名单收一下**：官方内置的是 **QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘**，并支持**自定义 MCP 连接器**。飞书、Discord、Gmail、GitHub、Notion、Jira、Slack 属于自行配置或社区生态。

**手机客户端随时可以同步你的账号和团队资料库**，还能再进一步——手机 App 可以连接自己的电脑、接管任务。桌面端 Windows 和 macOS 都支持，但**屏幕接管**（看实时桌面、虚拟键鼠）目前仅 Mac。

## 三、专家与专家团

- **单 Agent 专家**：解决单一专业问题（"高级开发工程师"专写代码，"小红书文案专家"专出爆款笔记）
- **Team 专家团**：团长自动拆解任务、并行执行、整合交付，适合多环节复杂工程

数据分析类专家团的典型接力是：**规划专家把控方向 → 数据分析师挖掘规律 → 报告撰写师转化为图文报告**。

专家中心按行业分类，有编程、电商、教育、金融、营销、游戏开发、数据运营、法务各种行业 agent，可以提前搜好专家让它针对性出方案。也能自由搭建专属的专家协作群。

**公司层面**同样能用：业务规划、行业咨询、商务开拓，专家团自动分配任务，团队负责人协同多个专家来做。

⚠️ 专家团的消耗比单专家高不少，召唤前先看余额。

## 四、Skills：把工作流封成资产

找各种软件提升生产力、不断收集长提示词核心词——正解是**资产复用**：把工作流打包成"救急锦囊"，AI 遇到类似问题自动去找。

```
                  ┌───────── WorkBuddy 协作体系 ─────────┐
                  │                                     │
           【 Skill（技能）】                   【 专家 / 专家团 】
     经验与作业流的“工具箱”                带行业人设与深度的“外脑”
     - 结构：skill.md + 代码/资料           - Agent型：搞定单点专业问题
     - 机制：按需匹配三级加载              - Team型：多Agent协同跑大任务
                  │                                     │
                  └──────────────────┬──────────────────┘
                                     │
                             ［ 组合落地应用 ］
                  例如：请「小红书运营专家」调用
                  「公众号/小红书搜索 Skill」完成深度产出
```

一个标准锦囊包含一个核心文件和三个可选目录：

- **`skill.md`（灵魂）**：名称和功能场景描述，确保能准确触发这个锦囊
- **`scripts/`（可选）**：自动化脚本，不用就不消耗 token
- **`references/`（可选）**：背景参考资料，需要时才动态读取
- **`assets/`（可选）**：看板模板、图片素材、字体等常用内容

**组合起来才是完整打法**：请「小红书运营专家」调用「公众号/小红书搜索 Skill」完成深度产出——专家给深度，Skill 给工具。

> 官方文档里我能核到的是「Skill 是独立的 SKILL.md 目录」，加上三条明确口径：① 非官方 Skill 可能存在恶意提示词注入、越权访问、后门程序等隐患，**优先用官方推荐 Skill**；② **关闭 ≠ 卸载**，关掉只是暂停调用、文件还在；③ **仅启用当前任务所需的技能**，减少误触发。
> 上面那个三目录 + 三级加载的结构，官方文档我没核到，实践里这么用没问题，但别写成官方承诺。

## 五、定时任务：三种来源，比频率重要

除了每天/每周/单次，官方还支持间隔、每双周、每月、每年，同一任务的多个执行日期写一条规则里就行；跑完能推送到企业微信，还能主动推送精炼摘要，历次结果和产物集中在"运行记录"里。

**但真正容易被忽略的是三种来源**：

| 来源 | 在哪跑 | 能读本机文件吗 |
|---|---|---|
| **本地** | 本机客户端 | 能，但执行期间别关电脑、别退客户端 |
| **项目** | 对应项目内 | 按项目权限，编辑和暂停要回项目里操作 |
| **云端** | 云端沙箱 | **不能** —— 电脑关机也照跑，但**提示词里别写本地路径** |

**云端这条意味着：可以让它在你关机的时候继续跑。** 代价是看不见你本机的文件，所以云端任务的提示词要写"去网上抓 / 去云端文档取"，而不是"D:\xxx\那个文件"。

不用只用它的模板：

- 自动抓取存在腾讯文档里的经营数据与价格变动，结合专家分析生成运营日报，存入资料库并推送到企微
- 自动从素材库挑选内容，套用各平台风格生成带排版的待发笔记与文章，你在手机上打开审稿台预览

### 三个工作模式 + 一层「项目」

**默认（Agent）** 直接执行 · **Plan** 先出方案等你确认 · **Ask** 只答不动手。

官方那句判断法值得抄：

> 如果「怎么做」比「做出来」更值得先讨论，就开 Plan。

跟前面"先给出第一版基础结构"是配套的，两个一起用，返工少一半。

还有一层很多人没用：**「项目」**把指令、连接器、专家、技能统一组织起来，成员发起任务时自动注入共享配置。项目里的「指令」是对 AI 的全局行为规则——团队用之前先把规则写清楚，比事后一条条补提示词省事。

## 六、Hy4 多了"眼睛"和"手"

Hy4 首次引入**视觉理解**和**电脑操作（Computer Use）**：能看懂截图、录屏、复杂图表；也能在图形界面和命令行里找按钮、点击、滚动、输入，然后**根据页面变化决定下一步做什么**。

官方演示包括做出可玩的复古 QQ 游戏街机厅、多轮修改教学课件 PPT、3D 场景构建和网页开发；Blender、CAD 这类专业软件做了专项训练。

**实际意义不是"AI 会打游戏"**，而是——**你不用再把屏幕上的东西翻译成文字喂它了**。销售后台截图、竞品页面一屏、扫描件，直接丢进去。

⚠️ Hy4 本身是语言模型，不直接生成图片或视频；发起图像/视频任务会自动切到专用多模态模型，不吃限免额度。限免期想省额度就别拿它批量出图，纯文本、代码、文档任务才吃。

顺着这条线，多模态其实是一整层：文生图/图生图、文生视频/图生视频、3D 模型、图像去水印与抠图修复、长音频转写（**支持方言和说话人分离**）、PDF 解析。**公众号那套封面图、章节配图、信息图、数据图表，不用再开第二个软件。**

## 七、三条实战链路

### 小程序：先验证逻辑，再谈资质

说清四件事就够：谁用、干什么（多用动词）、有哪些页面、需不需用户登录和保存存数据、界面什么风格。**扫码就能测试**。

需求文档可以一开始就写，也可以开发到一半让它反过来帮你归纳存档——这份文档以后给别的 AI 看，能省一整轮解释。

调用"微信小程序定制交付专家团"的完整链路是：**团队负责人**分配需求 → **产品经理**做市场调研 → **产品总监**规划原型和商业策略 → **架构师**分解工作流程和开发工期 → **程序员**开发 → **工程师**测试 → 交出**交付报告和功能清单**。

### 数据采集：复用你已登录的会话

浏览器自动化能做页面导航、数据快照、表格提取、表单填写，能自动翻页、筛选并存成文件。

关键一条：**先在浏览器里登录好目标平台（如 1688、数据后台），AI 复用你已登录的会话，不必把账号密码交给它。**

同时把范围写死：指令里严谨指定"抓取前几页"及排序方式，**控制在 10 页以内**，防止触发反爬被封；**去重、字段匹配、无效内容的处理规则写死**，这样能直接每天收到干净的表格。

### 公众号：一条能每天跑的流水线

从你的公众号提取 3-5 篇历史文章建账号人设 → 联网抓热点、拆高赞文章的高赞结构和文风 → 素材整合 → 去 AI 味 → 一次给多个标题（8 个）各自打分 → 结构化版式模板（主题 + 视觉规范）一次定义 → 按统一色板生成封面/配图 → 每日自动化结构化建稿 → 转公众号草稿箱。

粗稿 1800-2200 字带摘要和金句。协作审校放腾讯文档，长期存档放资料库。**微信聊天记录、语音转文字都能直接转化成素材。**

做成定时任务长期管理：搭一个公众号审稿台，每天打开让它自动往审稿台填充内容，你逐项审核，成品复制粘贴到公众号就行。**第一次要先手动跑通一次再启用定时**，涉及对外发布务必先验链路。

### 我自己在跑的一条

顺带说下我自己的：一条 RSS 抓取 → 分类 → 配图 → 人工审稿 → 发布的日更流水线（67 个源，每期 352 条、312 张图）。**先说清工具栈：这条是 CodeBuddy 侧那套 node 脚本，不是 WorkBuddy 客户端。**

有三条判断标准我觉得通用：

1. **分类我没让 AI 做，是规则引擎** —— 分类必须稳定复现（重跑 18 期往期数据，非分类字段差异必须是 0），LLM 每次输出都会漂移。**验收标准里含"必须可复现"的活，就别交给模型。**
2. **判断一个源能不能用，用实测出图率，不用感觉** —— 样本 ≥ 10 且出图率 ≥ 60% 才进白名单。而且**探测方式必须和生产链路一致**，否则测出的失败只说明"裸方式失败"。
3. **"AI 干完了但结果不对"，比"AI 没干完"更值得防** —— 我遇到过一次"线上不是最新"：所有部署证据都成立（字节级一致、构建全绿、页面全 200），真因是有一批数据是构建期只读的快照。定位三步：① 比对线上与本地的**原始字节** ② 按「**来源 @ 时间戳**」分组统计条目 ③ **某一批源时间戳完全相同 = 那批没刷新**。---

## 八、避坑清单（直接抄走）

- [ ] **不要全盘授权**：不要把工作空间直接设为桌面或 C 盘根目录，按"项目/店铺/日期"建立独立文件夹，处理速度快而且效果精准
- [ ] **涉及钱和法律的事情不全自动**：商品最终售价、法律风险合规承诺、重大文案发布，一定要亲自看清楚
- [ ] **定时任务必须先试跑**：务必在主对话里手动完整跑通一次、检查生成相关文件无误后，再打开定时开关
- [ ] **流水线提示词必加"异常兜底"**：*「若遇到数据缺失或读取失败，请立即停止并通知我，切勿使用预估值编造数据继续往下跑！」*
- [ ] **不要把相关 skills 技能和连接器同时打开多个**：技能装得多容易互相"打架"导致误触发，只保持当前任务所需的 2~3 个处于启用状态，用完最好关掉
- [ ] **召唤专家团前看余额**：消耗比单专家高不少
- [ ] **改文件前先备份**：AI 不是每次都稳定
- [ ] **别拿 Hy4 批量出图/出视频**：会自动切专用多模态模型，不吃限免

### 几个技巧

- [ ] **一次只改一个地方**；多说具体位置与属性（"把主标题字号改小一档、颜色换深蓝"），不说模糊感觉（"改得高级一点"）
- [ ] **提示词留余地**：长需求末尾加一句*「请先给出第一版基础结构，待我确认后再细化修改。」* 让 AI 集中精力把主干跑顺，避免过度脑补
- [ ] **浏览器提前登录**：让 AI 自动化采集前，在浏览器登录好账号
- [ ] **复杂任务找专家团**：多环节的深度分析直接呼叫"Team 专家团"，由主理人拆解、分析师计算、撰写师出报告，比单个 AI 问答全面得多
- [ ] **沉淀资产意识**：把改好的提示词做成模板，把常用的流程封成 Skill 和任务，把业务规章存进资料库，享受系统的复利
