## 一、新手篇：7 组「初级用法 → 建议用法」

### ① 初级用法：把 AI 当成高级搜索框

问两次看一眼总结，再点几句文尾的"你可能想问"就关掉。

**建议用法**：从"文字大模型"到"交付成品"。WorkBuddy 作为桌面客户端，可以产出完整的成品文件——文档、表格、PPT、网页，甚至小程序（PDF 主要是解析和读取，生成需要先导出）。

举例：以前问"agent 是什么意思"，是把百度百科、维基、行业论坛的文字汇总给你。

现在更进一步：让它把这份理解做成一页**可交互的 HTML 教学页**，改动留在结果区里回溯，接着追问继续迭代。

> 注：不是"自动生成动画教学 + 保留版本历史"。资料库里真实的机制是——**它改 MD 文档不覆盖原文，以"待确认"状态呈现，你接受后才写入**，随时能退回。

### ② 初级用法："帮我分析一下销售数据"

**建议用法**：提问包含这几个基本环节——

1. **你有什么**（数据库）：上传近期销售数据截图、业务报表和竞品销售情况
2. **你希望什么**（需求）：你的业务统计口径，目标是提高销售量、流量曝光，还是做销售策略调整
3. **你要什么**（目标）：明确输出文风、长度、使用场景（汇报/存档/教学/复盘/周报/求职）、格式（Markdown 报告、带公式的 Excel，还是 HTML 交互页）
4. **你要的结果**（成品）：给出验收标准与辅助要求（例如按利润率降序排前三、高亮亏损 SKU、给出三条落地建议）

**第 4 条是分水岭。** 没有它，你拿到的是"一篇看起来很像报告的东西"；有了它，你才能一眼验收。

如果讨厌写一句提问等 AI 思考半天，可以渐进式聊你的痛点和情况（所在行业、所在城市、销售计划、数据和最新竞品动态等），最后让 WorkBuddy 出一份综合报告，再针对其中关注的内容继续提问。

产出别只存本地——可以直接上传到**资料库、腾讯文档、ima 知识库、乐享知识库**，也能用链接 / 微信 / 企业微信分享，下次继续深入讨论。

### ③ 初级用法："WorkBuddy 生成的内容保存到本地改"

**建议用法**：用好资料库。资料库内置集成的是**腾讯文档、腾讯乐享、ima 知识库**（ima 下期可以聊聊这个，非常赞），另外还有官方套件 **Buddy One** 把 WorkBuddy、腾讯文档、腾讯会议、腾讯网盘、腾讯 ima 关联成一套账号，支持跨产品检索。

> 更正两处：**企业微信是消息推送和分享渠道，不是资料库组件**。**连接器**官方内置的是 QQ 邮箱、腾讯文档、腾讯乐享、腾讯会议、TAPD、腾讯网盘，并支持自定义 MCP——飞书、Discord、Gmail、GitHub、Notion、Jira、Slack 属于自行配置或社区生态，写成"一键打通"容易被挑错。

资料库的分工值得记一下：**MD 定内容、CSV 定数据、HTML 定表达**，三者互相引用。要沉淀的是判断标准，不是文件。

WorkBuddy 手机客户端随时可以同步你的账号和团队资料库。

### ④ 初级用法："假设你是 xx，你能够 xx，帮我 xx"

**建议用法**：用专家模式。WorkBuddy 提供专家和专家团两种协作方案——

- **单 Agent 专家**：解决单一专业问题（如"高级开发工程师"专写代码，"小红书文案专家"专出爆款笔记）
- **Team 专家团（多智能体接力）**：解决多环节复杂工程。如数据分析时：**规划专家把控方向 → 数据分析师挖掘规律 → 报告撰写师转化为图文报告**

可以在"专家中心"一键唤起，也能通过对话描述自由搭建专属的专家协作群。有编程、电商、教育、金融、营销、游戏开发、数据运营、法务各种行业 agent，可以根据需求提前搜专家，让它针对性出方案。

也可以邀请专家团给公司层面做商务落地、业务规划、行业咨询、商务开拓——专家团里包含多个角色，会自动分配任务，让团队负责人协同多个专家来做。

> ⚠️ 专家团的消耗通常是单专家的 3~5 倍，召唤前先看余额。

### ⑤ 初级用法：官网下载"微信开发者工具"开发小程序

**现在用法**：直接让它帮你制作。说清几件事即可——小程序**谁用、干什么**（对话多用动词）、**有哪些页面**、**需不需用户登录和保存存数据**、**界面什么风格**。

**扫码就能测试**，先帮你验证 vibecoding 的使用逻辑，再考虑资质和正式上架流程。

当然，你可以一开始就做一份需求文档，让它理解你开发小程序的定位、框架和目标；也可以开发到一半让它给你总结，方便这份文档归纳思路存档，别的 AI 也能通过这个文档快速理解你的软件。

举例：想开发一个女性用户为主的小程序，可以调用"微信小程序定制交付专家团"——

> **团队负责人**首先把需求分配给**产品经理**做市场调研 → 交给**产品总监**规划软件原型和商业策略 → 通过**架构师**分解工作流程和开发工期 → 接着由**程序员**开发小程序 → 再由**工程师**帮你测试 → 最终交出**交付报告和功能清单**。

### ⑥ 以前用法：定制数据爬虫去抓取汇总

**现在用法**：浏览器自动化 + 电脑操作，能做**页面导航、数据快照、表格提取、表单填写**四类动作，自动翻页、筛选，并把抓到的网页数据存成文件。

关键一条：**先在浏览器里登录好想抓取数据的平台（如 1688、数据后台），AI 直接复用这个登录态，不用把账号密码交给它。**

> 更正："绕过滑块和二次验证"这句建议删掉。准确说法是——**复用你已经登录的会话，不必交出凭据**。

说明：指令里严谨指定"抓取前几页"及排序方式，**建议控制在 10 页以内**，防止触发反爬机制被平台封禁。抓取时把**去重、字段匹配、无效内容的处理规则写死**，这样可以直接每天收到干净的表格。

### ⑦ 初级用法：打开公众号后台，打开多个标签页找热点开始写文章

**现在用法**：

从你的公众号上提取 **3-5 篇历史文章**建立账号标签人设 → 联网抓热点题材、补充资料、拆热门文章的高赞结构和文风 → 素材整合 → 去 AI 味 → **8 个标题各个打分** → 结构化版式模板（主题 + 视觉规范）一次定义 → 按统一色板生成封面/配图 → 每日自动化结构化建稿 → 转公众号草稿箱。

一次给多个标题、大纲，可以出粗稿 **1800~2200 字**正文、摘要和金句。协作审校放腾讯文档，长期存档放资料库。**你的微信聊天记录、语音转文字都能直接转化成素材**，历史文章和偏好也一起沉淀到资料库。

公众号的**封面图、章节配图、信息图、数据图表**也在这一环里（见第二节末尾）。

把这个工作流做成定时任务长期管理，比如搭一个公众号审稿台，每天打开让它自动往审稿台里填充内容，你逐项审核，最终成品复制粘贴到公众号就行。

> 第一次使用会需要大量连接各个授权。**官方建议的做法是先手动跑通一次，再启用定时**——尤其涉及外部发布，务必先验链路。

## 二、老手篇：这几个功能你多半没用过

### ① Hy4 有了"眼睛"和"手"

Hy4 首次引入**视觉理解**和**电脑操作（Computer Use）**：能看懂截图、录屏、复杂图表，也能在图形界面和命令行里找按钮、点击、滚动、输入，然后**根据页面变化决定下一步做什么**。

官方演示包括做出可玩的复古 QQ 游戏街机厅、多轮修改教学课件 PPT、3D 场景构建和网页开发；Blender、CAD 这类专业软件做了专项训练。

**实际意义不是"AI 会打游戏"**，而是——**你不用再把屏幕上的东西翻译成文字喂它了**。销售后台截图、竞品页面一屏、扫描件，直接丢进去。

> ⚠️ Hy4 本身是语言模型，**不直接生成图片或视频**；发起图像/视频任务会自动切到专用多模态模型（preview 期官方说明口径）。所以纯文本、代码、文档任务才吃 Hy4 的额度，批量出图另算。

顺着这条线，多模态其实是一整层：文生图/图生图、文生视频/图生视频、3D 模型、图像去水印与抠图修复、长音频转写（**支持方言和说话人分离**）、PDF 解析。**公众号那套封面图、章节配图、信息图、数据图表，不用再开第二个软件。**

### ② 定时任务有三种"来源"

除了每天、每周、单次，官方还支持**间隔、每双周、每月、每年**，同一任务的多个执行日期写一条规则里就行；任务跑完能推送到企业微信（个人也能注册使用），还能主动推送精炼摘要，历次结果和产物集中在"运行记录"里。

但真正容易被忽略的是**三种来源**：

| 来源 | 在哪跑 | 能读本机文件吗 |
|---|---|---|
| **本地** | 本机客户端 | 能，但执行期间别关电脑、别退客户端 |
| **项目** | 对应项目内 | 按项目权限，编辑和暂停要回项目里操作 |
| **云端** | 云端沙箱 | **不能** —— 电脑关机也照跑，但**提示词里别写本地路径** |

**云端这条意味着：可以让它在你关机的时候继续跑。** 代价是看不见本机文件，所以云端任务的提示词要写"去网上抓 / 去云端文档取"，而不是"D:\xxx\那个文件"。

也不用只用它的模板：

- 自动抓取存在腾讯文档里的经营数据与价格变动，结合专家分析生成运营日报存入资料库，并推送到企微
- 自动从素材库挑选内容，套用各平台风格生成带排版的待发笔记与文章，你在手机上打开审稿台预览

### ③ 三个工作模式，比很多提示词技巧值钱

**默认（Agent）** 直接执行 · **Plan** 先出方案等你确认 · **Ask** 只答不动手。

官方给的判断法值得抄：

> 如果「怎么做」比「做出来」更值得先讨论，就开 Plan。

跟第一节那句"请先给出第一版基础结构"是配套的，两个一起用，返工少一半。

还有一层很多人没用：**「项目」**把指令、连接器、专家、技能统一组织起来，成员发起任务时自动注入共享配置。项目里的「指令」是对 AI 的全局行为规则——团队用之前先把规则写清楚，比事后一条条补提示词省事得多。

### ④ 手机能接管电脑了

手机 App 可以连接自己的电脑、接管任务，看实时桌面、用虚拟键鼠操作。

**边界要说清**：桌面端 **Windows 和 macOS 都支持**"连接电脑"，但**屏幕接管**（实时桌面 + 虚拟键鼠）**目前仅 Mac**。前提是桌面端开启"允许移动设备远程连接"、电脑保持开机联网、同账号。

### ⑤ Skills：把工作流封成资产

找各种软件提升生产力、不断收集写长提示词核心词——正解是**资产复用**：社区大佬早就把日常流程做成了资产，把工作流和核心技能打包成一个救急锦囊，AI 每次遇到类似问题就会自动去找锦囊。

```
                  ┌───────── WorkBuddy 协作体系 ─────────┐
                  │                                     │
           【 Skill（技能）】                   【 专家 / 专家团 】
     经验与作业流的“工具箱”                带行业人设与深度的“外脑”
     - 结构：skill.md + 代码/资料           - Agent型：搞定单点专业问题
     - 机制：按需匹配三级加载              - Team型：多Agent协同跑大任务
                  │                                     │
                  └──────────────────┬──────────────────┘
                                     │
                             ［ 组合落地应用 ］
                  例如：请「小红书运营专家」调用
                  「公众号/小红书搜索 Skill」完成深度产出
```

一个标准的 skills 锦囊包含一个核心文件和三个可选目录：

- **`skill.md`（灵魂）**：包含名称和功能场景描述，确保能够准确触发这个锦囊
- **`scripts/`（可选）**：存放自动化脚本，不用就不消耗 token
- **`references/`（可选）**：存放背景参考资料，需要时才动态读取
- **`assets/`（可选）**：存放看板模板、图片素材、字体等常用内容

> **这里补一句我自己上次没核到的**：官方文档里能核到的是「Skill 是独立的 SKILL.md 目录」，外加三条明确口径——① 非官方 Skill 可能存在恶意提示词注入、越权访问、后门程序等隐患，**优先使用官方推荐 Skill**；② **关闭 ≠ 卸载**，关掉只是暂停调用，文件还在；③ **仅启用当前任务所需的技能**，减少误触发。
> 上面那个三目录 + 三级加载的结构，**官方文档我没核到**，实践里这么用没问题，但别写成官方承诺。

### ⑥ 组合落地才是完整打法

**请「小红书运营专家」调用「公众号/小红书搜索 Skill」完成深度产出**——专家给深度，Skill 给工具。这才是"沉淀资产意识"落到实处的样子。

## 三、顺手说说"审稿台"我自己是怎么跑的

第一节那条公众号审稿台，我自己搭了个类似的：RSS 抓取 → 分类 → 配图 → 人工审稿 → 发布的日更流水线，67 个源，每期 352 条、312 张图。

> 先说清工具栈：**这条是 CodeBuddy 侧那套 node 脚本，不是 WorkBuddy 客户端。**

有三条判断标准我觉得通用：

1. **分类我没让 AI 做，是规则引擎** —— 分类必须稳定复现（重跑 18 期往期数据，非分类字段差异必须是 0），LLM 每次输出都会漂移。**验收标准里含"必须可复现"的活，就别交给模型。**
2. **判断一个源能不能用，用实测出图率，不用感觉** —— 样本 ≥ 10 且出图率 ≥ 60% 才进白名单。而且**探测方式必须和生产链路一致**，否则测出的失败只说明"裸方式失败"。
3. **"AI 干完了但结果不对"，比"AI 没干完"更值得防** —— 我遇到过"线上不是最新"：所有部署证据都成立（字节级一致、构建全绿、页面全 200），真因是有一批数据是构建期只读的快照。定位三步：① 比对线上与本地的**原始字节** ② 按「**来源 @ 时间戳**」分组统计条目 ③ **某一批源时间戳完全相同 = 那批没刷新**。

## 四、避坑清单（可直接抄走）

- [ ] **不要全盘授权**：不要把工作空间直接设为桌面或 C 盘根目录，请务必按"项目/店铺/日期"建立独立文件夹，这样处理速度快而且效果精准
- [ ] **涉及钱和法律的事情不全自动**：商品最终售价、法律风险合规承诺、重大文案发布，你一定要亲自看清楚，避免不必要的风险
- [ ] **定时任务必须先试跑**：务必在主对话里手动完整跑通一次、检查生成相关文件无误后，再打开定时开关
- [ ] **流水线提示词必加"异常兜底"**：脚本或流水线提示词末尾，一定要加上这句——*「若遇到数据缺失或读取失败，请立即停止并通知我，切勿使用预估值编造数据继续往下跑！」*
- [ ] **不要把相关 skills 技能和连接器同时打开多个**：技能装得多容易互相"打架"导致误触发，只保持当前任务所需的 2~3 个 Skill 处于启用状态，用完最好关掉
- [ ] **召唤专家团前看余额**：消耗通常是单专家的 3~5 倍
- [ ] **改文件前先备份**：AI 不是每次都稳定

### workbuddy 技巧

- [ ] **修改注意**：一次只改一个地方；多说具体位置与属性（"把主标题字号改小一档、颜色换深蓝"），不说模糊感觉（"改得高级一点"）
- [ ] **提示词留余地**：在长需求的末尾加上一句——*「请先给出第一版基础结构，待我确认后再细化修改。」* 这能让 AI 集中精力把主干跑顺，避免过度脑补，方便你补充真实细节
- [ ] **浏览器提前登录**：让 AI 自动化采集前，在浏览器登录好账号
- [ ] **复杂任务找专家团**：多环节的深度分析直接呼叫"Team 专家团"，由主理人拆解、分析师计算、撰写师出报告，比单个 AI 问答全面得多
- [ ] **沉淀资产意识**：把改好的提示词做成模板，把你常用的流程封成 Skill 和任务，把业务规章存进资料库，享受系统的复利
