01

一条心智流

不要教「无差别监听 vs 激活监听」二选一

小白只记三句话

  • 在 Cursor 里 → 可以说「继续、发送」
  • 要写很长 → 点麦开始听写
  • 说完了 → 用按键收尾，或说取消

设置页不要这样写

  • ❌ 模式 A：无差别监听执行命令
  • ❌ 模式 B：激活后再执行
  • ❌ 让用户二选一「哪种监听」

Keys「语音命令」列表怎么改

左：现状问题 · 右：目标分组

现状问题（你截图里的）

  • 一条平铺列表：听写生命周期 + Agent 口令混在一起
  • 顶栏「套用当前习惯方案」像第二种模式 / 方案切换
  • 副文案塞语义 ID（input.cancel）和小字逻辑，小白读不动
  • 「待设置 / 仅语音 / 去收尾」三种状态，没有解释「这一页在干什么」
  • 不回答：什么时候能说、什么该配键

改法原则

  • 这一页只做一件事：给已有语音意图补按键
  • 对外叫「写字 / 下令」，不叫 A/B；用户不用背分类
  • 人话副标题；技术 ID 进 tooltip / 高级
  • 写字 3 行置顶；下令可选；更少用的折叠
  • 状态右侧只保留：已有键 / 建议补键 / 仅语音 / 去设收尾
语音已经会触发这些动作。本页只问：要不要再配一个键（手不离键时用）。不改口令、不是监听模式开关。

满额。先删一条或改成更怪的词再加。
冲突提示：若新增「发」——会与「发送」子串撞车，建议改用「确认发送」或改走按键。

后台听唤醒（高级 opt-in）

默认关

未打开时不占「常驻听」预算。打开后仍只听唤醒闭集，不是全文 STT。

小白压力怎么降

  • 默认不用填词表：Cursor 前台自动有 4 个短命令。
  • 想加第五个 → 界面说「已满」，引导改键或替换，而不是无限加。
  • 黄灯讲人话：「会和听写正文撞车」，不讲 contains / grammar。

和「24h 监听」的关系

没有 24h 语音监控。常驻感只来自「口令唤醒开着」。定额 + 默认关 + 空闲停听，一起管住。

07

Vibecoding 一日（用户自己怎么用）

零配置默认路径

开战

打开 Cursor → 自动「聆听中」→ 说「继续」或点 chip。

灌 prompt

点麦 → 「听写中」→ 说完按收尾键。

换场

离开 Cursor → 聆听自动停。去浏览器聊天不误触。

可选加速

设置高级里开「口令唤醒」；或 Keys 页给「继续」补一个键。
