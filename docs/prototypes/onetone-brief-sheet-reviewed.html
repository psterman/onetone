连续思路

不需要先分类

我想让首页帮助用户准备和 Agent 的第一次沟通

用户第一句原话 · 未经总结 UserOpening
⑥ 「第一句原话」要定义清楚，否则落不了地 如果这句话是用户在首页亲手写的第一句 → 规则成立（取正文首个句子/首段），零成本。 如果它来自剪贴板或语音采集 → 落不了地：observe_prompt() 在生产侧零调用方， hook 桥只接收 event 与 session_id，不携带文本。 建议先只支持「用户手写」，把采集来源留到接通 observe_prompt 之后。
⑦ 素材与正文之间是「附件」关系，不是「引用」关系 上一版素材挂在目标/背景/细节/计划下，能表达「这句话对应这张图」；本版正文是一整段， 素材挂在整篇下面，精确对应关系丢失了。 建议先接受附件模式（简单且够用），但导出时把每项素材的「你的话」内联排在正文之后， 而不是另起一节——Agent 真正要读的是：你的话 → 材料清单。
你的话 · 可以自由写下、粘贴或继续说
现在的问题不是没有工具，而是想法、截图、项目路径和过去的讨论散在不同地方。用户需要先把这些材料和自己的主线放在一起，说明它们为什么重要，再带着比较完整的上下文进入 Agent。第一次沟通越具体，Agent 需要猜的事情就越少。
提示 你已经说了想做什么和为什么。也可以补一句哪些内容绝对不能动。

Codex 修改了被标记为 NoTouch 的 src/index.html。这是依据文件 Diff 检出的疑似违规。

③ 这是整份稿子最有价值的新机制，而且落地极便宜 「不改什么」从一句自然语言变成了可机检的结构化约束，并且接上了反哺：确认违规 / 本次允许 = 用户判断 → 沉淀为下一轮约束。 检出这一步几乎不用写：dirty_fingerprint 已经在跑 git status --porcelain=v1 -uno， 只是把全文拿去算哈希；count_porcelain_changes 也只是数行。 把它解析成路径列表再与 guard 列表求交集，就是这条检出——约三行改动。 文件列表结构 DiffSummary.files: Vec<DiffFile{path,status}> 也已存在。
④ 缺了最关键的那个动作：还原 NoTouch 的含义是「这件事不该发生」。它既然发生了，用户第一想要的是退回去，而不是先去看 Diff。 而 cmd_tm_restore 已经存在（时光机恢复点），这是零成本的一个按钮——已补在第一位。 另：原稿没标这次返回来自哪次投递，违规判定需要 delivery → return 的关联，已补来源行。
