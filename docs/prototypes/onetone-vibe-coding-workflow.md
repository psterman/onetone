# OneTone Vibe Coding 工作流

## 核心判断

Vibe Coding 用户的主要需求不是获得一个答案，而是让一个模糊目标持续变成可验证的工作结果。首页应服务于这条循环：

```text
想法 → 上下文 → 计划 → 执行 → 预览/验证 → 反馈 → 继续或回退
```

首页因此应是一个可恢复的工作会话，而不是数据面板或 AI 搜索框。

## 用户工作阶段

| 阶段 | 用户心智 | OneTone 需要提供 | 首页表现 |
| --- | --- | --- | --- |
| 想法 | “我想做一个东西，但还没想清楚” | 连续对话、追问、目标提炼 | 新建会话 |
| 上下文 | “它需要知道我现在的项目” | 当前项目、窗口、文件、截图、历史 | 上下文摘要 |
| 计划 | “先做什么比较合理” | 可编辑计划、拆解、风险提示 | 当前计划 |
| 执行 | “帮我动手，但别失控” | Agent 操作、语音/按键触发、权限确认 | 执行状态 |
| 验证 | “结果对不对” | 预览、测试、错误、差异 | 结果卡片 |
| 反馈 | “这里不对，再改一下” | 继续对话、引用结果、重新规划 | 对话输入 |
| 恢复 | “我上次做到哪里了” | 会话历史、checkpoint、未完成任务 | 继续工作 |

## 首页信息层级

### 第一层：继续工作

默认优先展示最近一个未完成会话：项目、目标、最后结果、下一步建议。

### 第二层：当前会话

进入后保持连续对话。每条 Agent 消息可附带计划、操作、预览、测试和确认动作，但不把这些拆成互相孤立的页面。

### 第三层：上下文抽屉

上下文默认收起，按需展开查看：当前项目、前台应用、相关文件、最近修改、记忆和视觉输入。

## 首页状态

```text
empty       没有工作流：邀请用户说出想法
exploring   正在理解目标：允许补充上下文
planned     已形成计划：等待用户确认或修改
working     Agent 执行中：显示当前动作，可暂停
review      有结果待查看：展示预览、差异或测试结果
blocked     需要用户决定：明确说明原因和选项
resumable   上次有未完成工作：提供继续入口
```

## 原型验收标准

- 用户不用先理解 OneTone 的功能分类，就能开始工作。
- 首页能恢复上次会话，而不是只恢复一个项目名称。
- 用户可以在同一条对话中从想法走到执行和验证。
- 语音、按键、摄像头和 Agent 是当前会话的输入/执行能力，而不是平行入口。
- Agent 每次行动前后都能说明“准备做什么、做了什么、下一步是什么”。
- 用户可以继续、暂停、修改计划、回退，不会被迫重新开始。
