评估结论与修改清单

总体：这是最好的一版，状态机取代了视角选择，方向锁定。六态 + 一个主按钮 + 一条状态条，用户不再被问"你现在要看哪个视角"。空态终于成为默认态，「现在才需要决定交给谁」是决策七最彻底的一次落地。

必须改（P0）

  1. ② 拆开「完成排版」这个黑箱。它把「带哪 3 项 · 每项什么档位 · 留哪 2 项」三个用户判断藏进一次点击，且没有任何依据说明。改名「装订并预览」+ 把依据写在明处。
  2. ③ 把「你的话」补回来。这是本版最大回退：素材说明字段整个消失，只剩"只读"那一半。
  3. ⑧ 修目的地变量。三个通道选项点不动，选 Cursor 后全界面仍写 Codex——选了等于没选。
  4. ⑨ 修状态倒退。装订后加素材会 state='COLLECTING'，已写好的正文被藏起来。

应该改（P1）

  1. ⑤ 补溯源三件套：来源 / 采集时间 / 指纹 / [回到来源]。sha2 已在依赖里。
  2. ⑦ 把保护边界加回来（连续两版缺席，三行代价）。
  3. ⑥ 装载放进目的地面板（决策七：预算发送时可见）。
  4. ④ 档位 pill 改成真按钮，切换联动装载。
  5. ⑩「整理」改名「排序」并写明规则。
  6. ⑫ 状态机预留第七态「本轮返回」，否则阶段四会牵动整个 render。

别动的三样

  • 回执里的「? 无法确认是否发送」——全套最诚实的一个字符，对应 insert_text_no_enter 不发 Enter。
  • 空态是默认态（data-state="EMPTY"）——冷启动确实是常态。
  • 通道条只在 CHANNEL_SELECTED 出现——写作期不暴露目的地，这条非常对。

一个判断

状态机的代价是不可逆：这六态没有任何"退回去"的入口。用户点错一步只能重来。建议至少允许 ASSEMBLED ↔ COLLECTING 双向——真正的纸是可以随便改的，状态机比纸严格，这是它有风险的地方。
