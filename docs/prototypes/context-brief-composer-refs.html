思路整合器 · 参考案例与 OneTone 原型

把首页从"状态看板"改成"上下文装配台"：用户点选各类元素，在编辑框里拼成一份简报，一次性发给 agent。 本文件收录同类产品做法、核对 OneTone 的元素数据供给，并给出一版可交互原型。

〇、定位纠正：这是「首次沟通准备器」，不是上下文装配器

用户纠正：首页是帮用户规划思路，不是代替 agent 整理——提前做好进入 vibe coding 的准备，最终反哺下一次操作， 避免因抽象导致 AI 理解偏差，通过前期对材料的精准投喂和规范，让各种思路融合进主体思维，和 agent 形成一次有效的首次沟通。

这个纠正换了三件事

维度我上一轮的理解（错）纠正后
对标物VS Code Copilot / Continue 的上下文装配不是"装多少上下文"，是"消除多少歧义"
度量装了几类元素、多少 token首次沟通一次就对的概率；抽象词有几个、悬空指称有几处、验收判据是否可观察
方向面向 agent 的投喂工具面向用户自己想清楚的工具，投喂是副产品

推论一：MD 编辑器恰恰是抽象的温床，容器必须是模板

空白页没有约束力，用户在空白页上会写"把首页优化一下，好看点"。要避免抽象，靠的不是让用户多写，而是让字段逼他把话说具体。 所以主体不该是自由 MD 编辑器，而是「结构化字段 + 素材引用」——MD 只是导出格式。

推论二：五种偏差，对应五个强制字段

偏差机制抽象长什么样强制字段检测规则（纯规则，不用 LLM）
目标无边界"优化一下""改进""完善"目标抽象动词词表命中即告警
现状不明AI 不知道现在什么样，只能猜现状与证据字段为空、或未挂任何素材 → 告警
范围不明"首页"是哪些文件？范围无路径/文件名/模块词 → 告警
验收不可观察"好看点""合理一些"验收无数字/文件名/命令/步骤词 → 告警
约束未声明AI 顺手改了不该改的不改什么无否定词（不要/别/除了/保持）→ 告警
指称悬空"这个""那个""跟上次一样"素材引用代词语料 + 无引用 → 告警

分歧点值得单独说：LLM 绝不能用来"润色"这份简报。润色就是重新引入抽象——把用户刚逼自己说具体的话，又抹平回"优化一下"。 模型在这里唯一被允许的角色是"检查完整性"，不是"代写"。这也让上一轮"不用 LLM"的结论有了更强的理由：不是省成本，是模板的强制性不能被模型软化。

推论三：反哺这条回路，数据层已经预留了位置，只差写入

已存在的字段在闭环里的角色
memory_records.user_authoredMIGRATION_V3 专门加的——区分"用户自己写的"和"系统推断的"。这就是"不代替 agent 整理"这条边界在数据层的对应物：所有 user_authored = 0 的内容在 UI 上必须标"系统观察"，不能混进"我的判断"
memory_records.supersedes_id记忆可修订而非堆积。反哺时覆盖旧约束，不会留下一堆互相矛盾的历史

agent_checkpoints.next_action / pending_questions_json前者就是"下一次的起点"；后者是"未决问题"——恰好是歧义的残留物
agent_checkpoints.current_task / changed_files_json上次做到哪、改了什么 → 下次简报"现状"字段的现成素材

决策：填空题，还是简约直发？

答案是默认简约，按需填空——但"按需"的依据不是用户想不想填，而是素材本身有没有把歧义消掉。素材越充分，一句话的容忍度越高；左下角那一格（素材少 + 话抽象）才是填空题唯一该出现的地方。

原则说明
默认简约主界面就是"扔素材 + 一句话"，零字段、零仪式感。五个字段不是默认界面，是被触发的补丁。
只问一句，就地问检测到问题时不要弹表单，只在输入框旁问风险最高的那一句：「"优化"具体指什么？截个图圈出来」。问一个比填五个有效得多。
门禁必须是软的这一条是我上一版的错，已改。原型的红灯硬门禁（有硬伤禁用发送）本质上就是变相填空题——它强迫一个还没想清楚的人假装想清楚。改成：允许发，但诚实告知哪条最可能跑偏。
填空的价值在发送后用户填过的东西必须沉淀（接上一节的反哺回路）。于是老用户看到的补丁越来越少——历史约束已被自动回填。不要让新用户填空，让老用户的填空自动消失。
判断题优于填空题人在"识别错误"时远比"回忆需求"时准确。所以另一条解法是：让 agent 先复述它的理解，用户来纠正——纠正一个具体的错误描述，比从空白开始描述容易得多。这不违背"不用 LLM"：那个模型是目标 agent，不是 OneTone 自己调的。

原型 · 五个字段 + 歧义检测（实时、纯规则、不用 LLM）

左边填，右边实时体检。两个示例可载入：「抽象示例」是典型的一句模糊话，「规范示例」是同一件事说清楚后的样子。
注意：这五个字段不是默认界面。默认应该是"粘贴 + 一句话"，这五个探针只在检测到问题时就地问一句，而且只问风险最高的那一句——右下角面板演示的就是这个"先问这一句"。

首次沟通简报

歧义体检

方案 A：思考工作流模板（第一性原理 / 逆向思考 / …）

先纠一个前提：flomo 的「AI 洞察」不是模板库。它是一个读过你所有笔记的 LLM——输入一个主题，从历史记录里提炼你没意识到的模式。官方边界写得很明确：「AI 洞察是一面镜子，只会基于已有笔记进行分析」，且要满 50 条笔记才开放试用。
这条边界在这里是致命的：洞察的价值 = f(已积累的记录量)，而简报恰恰发生在历史为零的那一次——flomo 在你最需要它的地方失效。
真正能借的是它的「回顾」机制（每日回顾 / 随机漫步 / 相关笔记：让旧记录主动回到当前语境）。那一层在 OneTone 的对应物就是反哺（memory_fts 检索 + 自动预填）。flomo 教的不是"做模板库"，而是"让历史来敲门"。

候选产物落到判定说明 / 改造办法
逆向思考
这怎么会失败		验收 + 不改什么直接可用唯一天然产出可观察失败判据的模板——失败的样子反过来写就是验收标准。四个候选里优先级最高。
第一性原理现状与证据需强制产物格式极易滑向"回归本质"这种更大的抽象词。必须规定产物 = 「我现在能确定的事实只有 N 条」（N ≤ 5，每条要能挂素材）。否则它比不填更糟。
价值取舍不改什么（限本次）需限定作用域限定成"这次改动里哪两件事冲突时先保哪个" → 可用；一旦滑到人生价值观 → 失去可执行性。
MBTI 分析不进任务字段类别错误产物是自我认知，不是任务规格。agent 拿到"我是 INFJ"执行不了任何动作。它有位置：长期记忆层 memory_records（user_authored = 1），导出时作为「关于我」附在末尾、可选开关。

四条约束——否则模板会变成新的抽象来源

约束说明
模板不是清单，是补丁不做"模板库"。默认不出现，只在检测到缺口时递上一个（验收缺失 → 递"逆向思考"）。这与上一节"只问一句"是同一条原则，不是两套设计。
模板不豁免检测选了模板照样过歧义体检。第一性原理写出"回归本质"照样亮灯——这正是"模板的强制性不能被软化"的延续。
过程提示与产物分离思考工作流是过程，简报要的是产物。模板 UI = 过程提示 + 产物框，导出时只带产物框。否则你发给 agent 的是一篇随笔。（民间 LeanPrompts 的 %%注释%% 注入前剥离，正是这个机制。）
让数据淘汰模板记录每个模板产出的简报，用验收台上"保留 / 放弃"的结果回流统计命中率。跑三个月，留下的不超过三个。不是你设计模板库，是数据替你筛出模板库。

原型 · 模板抽屉（选一个 → 填空 → 照样过检测）

点一个模板，看它问什么、产物落进哪个字段。「按提示写」会让上面的体检归零，「写成空话」会照样亮灯——选了模板不等于免检。
MBTI 那一格演示的是第二种失败：它能通过检测，但 agent 拿它执行不了任何动作。所以准入标准必须是"能否映射到字段"，而不是"能不能过检测"。

二、三种 UI 形态，以及为什么多数人不做"完整编辑器"

A · 内联 chip
一行输入框 + 若干 chip
  • 成本最低，token 天然可控
  • 但装不下"一段思路"——超过 5 个 chip 就糊
  • 代表：VS Code、Continue、Cursor @
B · 来源面板
侧栏集合，整包开关
  • 可核验性最强，溯源不断
  • 但用户不能在里面"写想法"，只能问
  • 代表：NotebookLM、Projects
C · 草稿板
可编辑文档，素材成块嵌入
  • 唯一能承载"思路整合"的形态
  • 代价：token 失控 + 溯源易断
  • 代表：Cursor Notepads（beta）

行业里刻意不做完整 MD 正文编辑，有三条真实理由：① 可编辑 = 可失真，引用不再指向真实来源；② 正文让人容易塞过量内容，而 chip 有天然预算；③ 编辑器成本比 chip 高一个数量级。 你要做的是形态 C，就必须主动把前两条代价补回来 —— 这就是下面原型里"素材只读"和"预算条"两个设计的由来。

七、必须现在就定的四个决策

1 · 素材只读，只有"你的话"可编辑
这是这个方案最容易翻车的地方。一旦允许改素材内容，NotebookLM 那种"可回跳原文"就断了，而诚实可核验是你目前唯一有满分潜质的维度。原型里切到"素材可编辑"，你会看到溯源标签变红。
2 · 预算条必须可见，且能"折叠为摘要"
VS Code 的做法是可以抄的：每个素材有 全文 / 摘要 两档。会话历史这类元素动辄几千 token，默认只能进摘要档。
3 · 托盘要能自动攒，不能只靠手点
冷启动空托盘是这个方案的第二大风险（第一是上面那条）。OneTone 是桌面应用，可以常驻感知剪贴板、前台窗口、文件变更，做到 Dia 在浏览器里做的那件事：不是你去收集上下文，而是上下文来敲门。
4 · 简报要持久化，别发完就散
这是市面上没有的一维：别人是单一 agent 的上下文装配，你是多 agent 编排。所以简报应成为对象——可复用、可改投别的 agent、可版本化。否则它就只是一次性输入框，白做了编辑器。

未决：截图这一类（红）要不要做。它价值最高但需要从零新增 OS 截屏能力；建议先做"从剪贴板读图片"（已有写入侧基础设施，成本远低），验证用户真的会往里塞截图之后，再决定要不要做自动截屏。
