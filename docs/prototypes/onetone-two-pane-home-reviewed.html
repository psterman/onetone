⑦ 最严重预览内容 ≠ 当前引用引用区 2 项、底栏写 2 项，但这里的 source-box 里出现了 3 项——多出「项目目录 E:\voice-pilot」。在一个以可核验为核心价值的产品里，这是致命的：用户以为发出去 2 项，实际 3 项。修正模式下预览由引用区实时编译，数字永远一致。

⑨ 回退保护边界在这一版消失了上一版有 NoTouch · src/index.html / KeepStyle，这一版没有。它是全套约束里唯一能被机器检出的：git status 路径列表 ∩ guard 列表，DiffSummary.files: Vec<DiffFile{path,status}> 已在 time_machine/types.rs:152。修正后预览会带上它。

评估结论与修改清单

总体：这是目前最干净的一版，方向锁定，可以进入实现。两栏 + 底部发送条 + 抽屉，正是决策七；「第一句话就是标题，不做 AI 改写」「机械装订，没有使用 LLM」「已准备填入，尚未发送」这三句文案是全套稿子里最诚实的部分，一个字都别改。

必须改（P0）

  1. ⑦ 预览 ≠ 引用（3 项 vs 2 项）。在可核验产品里这是致命缺陷。改为：预览由引用区实时编译，不存在第二份手写副本（同时也解掉 ⑧）。
  2. ⑤ 素材补溯源三件套。来源 / 采集时间 / 指纹 / [回到来源] / 原文未修改。sha2 已在依赖里，零成本。
  3. ⑥ 「你的话」与素材分栏。现在是同一行，读者分不清哪句是原文。

应该改（P1）

  1. ⑨ 把保护边界加回来。上一版有 NoTouch / KeepStyle，这版掉了；它是唯一可机检的约束。
  2. ⑪ 抽屉可改投 + 显示装载。换目的地要联动待办与预算。
  3. ② 候选与已用分流。加忽略、撤销批次、常驻「● 正在感知 / 暂停」。
  4. ① 顶部给简报身份。名称 · 版本 · 投递次数。H1 当标题导致两份简报无法区分。

小修（P2）

  1. ③ 「整理」改名「排序」并写明规则——它违反「不代替用户整理」。
  2. ⑩ 预算写全：正文 + 材料 ≈ 总数 · 上限未知 · 无 tokenizer。不画比例条。
  3. ④ 两条「待确认」要能点（加入 / 忽略）。

别动的三个亮点

  • 「已准备填入，尚未发送」——事实口径。实现上 insert_text_no_enter 确实不发 Enter。
  • 「第一句话就是标题，不做 AI 改写」——且 observe_prompt 至今零写入方，标题只能手写，这句恰好是对的。
  • 添加菜单里的「◉ 说话」——语音通道入口，浏览器产品做不到的东西，改版时别丢。
