# OneTone 真正继续：首页契约

## 目标

首页不负责解释所有能力，只负责把用户带回最近一个真实工作状态，并提供一个可以立即执行的下一步。

## 唯一数据来源

首页使用 `cmd_agent_home_snapshot` 返回的 `AgentHomeSnapshot`，不再使用独立 demo fixture：

- `project`：当前工作区与项目身份
- `activeSession`：当前 Agent/session 与状态
- `recentSessions`：同项目的最近会话
- `recentEvents`：最近真实事件
- `checkpoint`：可恢复的任务快照
- `context`：项目上下文与记忆

继续操作调用 `cmd_agent_checkpoint_resume(sessionId)`，恢复结果必须回写当前 session，并刷新首页快照。

## 默认首页决策

### 有可恢复 checkpoint

主区域显示：

```text
继续上次工作
项目 / session
上次完成的动作
当前停在的步骤
下一步动作

[继续：下一步动作]
```

主按钮必须绑定 checkpoint resume，而不是打开一个静态详情页。

### 有进行中的 session

主区域显示当前 Agent 正在做的具体事情：

```text
正在进行
任务标题
当前步骤
最近事件

[查看现场] [暂停/停止]
```

不要显示虚假的百分比；只有 provider 提供真实进度时才显示进度。

### 有待确认请求

主区域直接显示等待用户处理的原因：

```text
需要你的决定
Agent 正在等待：具体问题

[批准] [拒绝] [补充说明]
```

这类状态优先级高于普通恢复任务。

### 只有已完成 session

显示最近完成的结果，并把主动作改成：

```text
[继续这个项目] [新建工作]
```

### 没有任何 session

才显示空状态入口，但入口仍然需要先绑定当前项目：

```text
选择一个项目，或从当前窗口开始
[选择项目] [读取当前窗口]
```

## 首页最小视觉结构

```text
顶部：当前项目 + 当前 Agent

中央：一个主状态
      一句明确解释
      一个主动作

底部：继续对话 / 语音输入

侧边：默认隐藏的上下文、事件和会话历史
```

## 不再允许的原型行为

- 点击“继续”只切换页面
- 用静态文本假装 session 已恢复
- 用 demo 任务代替真实 checkpoint
- 把所有功能卡片同时铺在首页
- 用进度条推测 Agent 状态
- 把项目名当成工作恢复

## 验收

1. 重启软件后，首页可以显示真实项目与 session。
2. 主按钮调用 resume，并能看到状态变化。
3. resume 后显示真实最新事件，而不是固定文案。
4. 没有数据时明确区分未授权、无项目、无历史和读取失败。
5. 首页所有主动作都能映射到已有 IPC 命令或明确标记为尚未实现。
