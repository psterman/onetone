OneTone · UI 分析与改版建议 · 2026-07-07

把「按键 + 语音」合进"我的习惯"

当前主页是「按键唤起 / 语音唤起」两块并列面板,设置页又把"按键"、"语音"、"我的习惯"切成三个独立入口。 但习惯本身就是横跨这两块的情景模式——"我的习惯"面板自己的副标题已经写得很清楚了: 「你在按键和语音里保存的情景模式会自动汇入这里」。问题在于它被埋了。

这份方案分三段:先拆解现状、再说语音界面怎么改、最后给"情景模式融入习惯版块"的融合设计。

总览:主页 + 设置 + 习惯三层联动

这个融合方案的本质 不是再加新页面,而是承认一个事实:按键和语音从来就是同一个习惯的两条腿。把"腿"拆成独立菜单(按键 / 语音 / 习惯)只是工程视角,不是用户视角。用户视角只有一件事——"我在用什么情景"。把这件事在视觉上做主角,其他都是它的子页面。
§ 05

实施路线:四步走,不重写

基于现有 IA 改版(docs/HABIT_IA_BEGINNER_FRIENDLY.md)之上增量推进,每一步都能独立发版。

步骤拆解

  1. STEP 1 · 1 周 主页双面板视觉对齐

    不改结构,只把语音面板升级成与按键面板对称的"三段式"。同步加"所属习惯 X"归属行。最小风险。

  2. STEP 2 · 1 周 header 加情景切换条

    把 homeSchemeSwitcher 提到 header 顶部,改成横排 chip 条。主页右上角原位保留 fallback。

  3. STEP 3 · 2 周 习惯详情加 Tab ② 语音

    从 settingsPanelVoiceWake 迁移:引擎 / 唤醒词 / 麦克风 / 结束词 / 自动发送 / 置信度全部收纳进习惯详情。"编辑语音"跨页跳转取消。

  4. STEP 4 · 1 周 设置侧栏收掉"按键 / 语音"

    侧栏从 5 菜单 → 3 菜单("基础 / 我的习惯 / 运行状态")。旧菜单保留 30 天重定向,渐进式迁移。

风险与回退

风险应对
老用户找不到"按键 / 语音"Step 4 用 feature flag,旧菜单保留 30 天
习惯详情页变得太长Tab ② 默认折叠"高级选项",只露出常用项
header chip 条超出宽度超过 5 个自动隐藏第 5+ 个到 "+ 更多"
从"情景模式"视角看配置项每个 Tab 内字段按"通用 vs 该情景专属"分组
多习惯的语音设置冲突已有 OneToneSceneConfig.resolveEffectiveScene 处理
做完后建议做的最后一件事 把"习惯"两个字,在面向用户的文案里替换成"情景模式"(或并列展示 "习惯 · 情景模式"),消除认知差。homeLiveUnset / settingsPanelHabitsTitle / habit-hub-empty-title 这些 key 都值得一起改。OneTone 用户群对"模式"这个概念比"习惯"更熟(practice.js 用的就是 phrase practice)。
