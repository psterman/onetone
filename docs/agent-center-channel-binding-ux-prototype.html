首页主行一个字节都不加。通道是实现细节，用户在首页能做的只有「点按钮」。 它真正该露面的时刻是：动作之后、按钮为什么灰、通道打架。

首页主行 零改动

状态点 · 名称 · 控制态 · 项目 · 时间 · 三个动作 —— 到此为止。

Cursor 正在工作 · 5 分钟前 voice-pilot 5 分钟前 聚焦 继续 停止 ▾

不加通道信息。用户触发 Cursor 的方式就是这三个按钮，按钮已经在这儿了 —— 再告诉他「按键已绑定」，看完没有下一步动作。

瞬间一 · 点了「停止」之后 回执里说清走的哪条路

尽力而为的 Agent，回执必须告诉用户「去哪儿看结果」。

! 已发送停止指令 已通过按键发送停止指令 Cursor 可能还在运行 —— 请到 Cursor 窗口确认是否真的停了

现在：一行 toast「已发送停止指令，请自行确认」，没说走的是按键还是别的，也没说去哪儿确认；首页不留痕，消失即忘。 另两态文案：成功 →「已确认 Agent 停止」；失败 →「停止失败 · 没有可定位的 Cursor 控制目标」。

瞬间二 · 「停止」为什么是灰的 让已有的原因逻辑跑起来

灰按钮现在只能靠悬停 tooltip 猜。改成可点，点击就说出原因。

Cursor 状态已过期 聚焦 继续 停止
? 现在还不能用停止 没有可定位的 Cursor 控制目标 —— 先打开 Cursor 并让它处于前台

现在：按钮是 disabled，点击根本不触发，dispatchAction 里那段「toast 出原因」的代码永远走不到； 原因只剩 title 悬停可见，触屏和键盘用户看不到。

瞬间三 · 通道打架 唯一值得在首页常驻的通道信息

同一个按键绑给了两个应用 —— 这事用户只会在首页撞见，而且只在打架时才需要知道。

按键 F13 同时绑给了 Cursor 和 Windsurf，触发时以当前前台应用为准

现在：没有这条。用户按了键，结果落在另一个应用上，只会以为「停止没生效」。 形态是告警不是清单 —— 不打架时首页什么都不显示。
