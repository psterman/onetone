A：主行只有聚焦 / 继续 / 停止。快捷方式全部留在设置页 —— 首页最干净，但「透过快捷操作方式管理」这一半在首页没有落点，用户得主动去设置页才知道有按键和软键盘可用。 Claude / Codex 这类命令行 Agent 同样不显示任何方式入口。

B：动作区多一个「方式」，点开是三件能直接做的事（按 F13 / 打开软键盘 / 去配置语音），不是绑定状态清单。 只对有应用目标的 Agent 出现；命令行 Agent 不显示这个按钮。代价是主行多一个元素，窄屏需优先隐藏项目名称列。

两个方案的差别 其余部分完全相同

主行元素 A：聚焦 / 继续 / 停止 B：聚焦 / 继续 / 停止 / 方式

展示形态 无 可执行动作，不是「已绑定」状态
窄屏 ≤680 主行一行放得下 需先隐藏项目列，再考虑收起「方式」
新增成本 0（只把主行第二行换成监视态） 需要一个下拉面板 + 三个可执行动作

两个方案都含同一处改动：主行第二行由控制态（可确认停止 / 尽力停止）改为监视态（在跑 / 最后活动 / 观察新鲜度）， 控制能力移到按钮与展开区。统计格也按支柱拆成观测组与控制组。 视觉取自 home-agent-roster.css 与 agent-center.css。原型未改动生产代码。
