# 思路简报系统 · 四项产品级约束（2026-10-06 锁定）

> 状态：**已锁定**。改动首页 / 简报相关实现前必读。
> 相关原型：`docs/prototypes/onetone-brief-system-locked.html`（锁定版，已实现本文全部交互）
> 相关讨论：`docs/prototypes/context-brief-composer-refs.html`

## 定位

首页不是一次性上下文编辑器，而是：

> **可追溯素材库之上的、受预算约束的、可持续复用的多 Agent 简报系统。**

更精确的说法：

> **一个以只读素材为证据、以"你的话"为主体、以预算为约束、可以跨 Agent 持续演化的思路简报系统。**

## 决策一 · 素材永远只读

**锁定规则**：原始素材不可编辑。用户只能编辑「你的话」、素材说明和引用方式。

素材进入 OneTone 后至少保留：`原始内容 / 来源 / 来源位置 / 采集时间 / 文件状态 / 内容指纹 / 可否回跳`。

- **派生内容不能覆盖原素材**：全文、摘要、裁剪、OCR、代码片段、Agent 生成摘要都是派生视图，每个都必须保留到原素材的关系。
- **摘要必须标类型**：`用户编写` / `结构提取` / `Agent 生成`。不标的话，"摘要"会成为新的不可核验内容。
- **素材变化不静默替换**：本地文件被外部编辑时，必须提示（简报引用版本 vs 磁盘当前版本），并给出「继续使用原版本 / 更新为当前版本 / 查看差异」。更新生成**新素材版本**，不覆盖旧版本。

### 落地事实
- `sha2 = "0.10"` 已在 `src-tauri/Cargo.toml:55` → 内容指纹可直接实现，无需新依赖。
- 采集时间 / 来源 / 来源位置：需新建字段（现有表无对应列）。

## 决策二 · 预算常驻，可折叠为摘要

**锁定规则**：每份简报都必须显示**面向目标 Agent** 的上下文预算，放在页面顶部或底部，不藏进弹窗。

- 目标 Agent 改变 → 预算重新计算（Codex 32k / Cursor 128k / Claude 200k）。
- **无法获得准确 tokenizer 时必须显示"估算值"**，不能伪装成精确数据。
- 每项素材三档：`摘要 / 全文 / 不发送`。

默认档位：

| 素材类型 | 默认模式 |
|---|---|
| 项目路径 | 引用 |
| 小段用户文字 | 全文 |
| 小型 Markdown | 全文 |
| 大型文件 | 摘要 |
| 历史会话 | 摘要 |
| 网页 | 标题、网址和用户说明 |
| 图片 | 图片与用户说明 |
| 二进制文件 | 文件引用 |

### 无 LLM 时的摘要来源（边界）
无 LLM 阶段**只能**用：① 用户自己写的；② 来源已有的摘要或标题；③ **结构性摘要**（文件名/路径/大小/标题层级/前后若干行/修改文件清单/会话时间·轮次数·命令记录）；④ **抽取式片段**（用户手动选择的段落、用户标记的重要内容）。

**"摘要"不得被当作自动语义总结。** 这也是"不用 LLM"结论的更强理由：确定性 = 可复现 = 可核验。

### 落地事实
- **全仓库零 tokenizer**：`grep tiktoken|tokenizer|count_token|estimate_token` 在 `src-tauri/src` 无命中（唯一命中是 `memory.rs:235` 关于 FTS 分词器的注释）。
  → 预算条**只能**是估算值，必须带「估算值」标记。这与本决策的要求一致。

## 决策三 · 托盘自动积累候选素材

**锁定规则**：系统可以自动发现候选素材，但**未经用户确认，不能自动进入简报**。

流程：系统感知到活动 → 生成候选素材 → 进入「刚刚发生」托盘 → 用户决定是否加入、加入哪里、如何引用。

### 三个权限层级
1. **仅感知**：只知道发生过什么（当前应用名、窗口标题、文件发生变化、剪贴板类型、Agent 会话活动），**不读正文**。
2. **本地暂存**：读取并短暂保存在本机候选区（剪贴板文字、截图、文件路径、网页地址），可设自动过期。
3. **自动加入**：只对用户明确授权的规则生效。示例默认规则：
   - ✓ voice-pilot 目录内的新截图
   - ✓ Codex 当前会话产生的 Diff
   - × 密码管理器剪贴板
   - × 隐私窗口
   - × 其他项目文件

### 必须有的隐私控制
暂停感知 / 清空候选托盘 / 应用排除列表 / 目录白名单 / 敏感字段过滤 / 候选内容自动过期 / **明确显示正在监听什么** / 所有内容默认只在本地。

视觉上必须常驻状态：`● 正在感知 · 剪贴板 · voice-pilot · Codex [暂停]`。

### 落地事实
| 能力 | 现状 |
|---|---|
| 文件监听 | `notify = "6"` 已装在 Cargo.toml，**但 `src-tauri/src` 零使用**（需新建 watcher） |
| 剪贴板读取 | 仅 `CF_UNICODETEXT` 一条（`agent/insert_text.rs:106`）；**图片读不了**；无监听（需轮询） |
| 前台窗口识别 | `app_identity.rs` 已有（winapi + tlhelp32） |
| 浏览器网址 | `cmd_list_browser_bookmarks` 已有（在 `prefs.rs`） |
| 窗口拖放 | **红**：`tauri.conf.json` 未开 dragDrop，Tauri 2 默认关闭 |
| 自动截图 | **红**：全仓库无 capture_screen |

## 决策四 · 简报成为持久对象

**锁定规则**：简报不是输入框内容，而是可以保存、版本化、复制和投递的工作对象。

数据关系（建议）：

```
项目
 └─ 简报
     ├─ 简报版本
     ├─ 用户文字
     ├─ 素材引用
     ├─ 素材引用模式
     ├─ 目标 Agent
     ├─ 预算快照
     ├─ 交付记录
     └─ Agent 返回材料
```

支持：保存草稿 / 自动保存 / 创建新版本 / 查看两版本差异 / 复制为新简报 / 改投另一 Agent / 为不同 Agent 保存不同引用策略 / 记录交付时间与目标会话 / 回收 Agent 响应与结果 / 从结果创建下一版简报。

### 改投不同 Agent ≠ 换下拉框
不同 Agent 能力不同（例：图片在 Codex 需手动上传、Cursor/Claude 可附加）。**主体简报不变，投递配置形成分支**。

### 版本化
每个版本保留：当时引用的素材版本、当时的用户文字、当时的预算、发给哪个 Agent、Agent 返回了什么、用户如何判断结果。

### 落地事实
- 现有表：`projects` / `agent_sessions` / `agent_events` / `provider_cursors` / `agent_checkpoints` / `memory_records` / `agent_registry`。**无 `brief*` 表** → 需新建 MIGRATION。
- 可复用的既有语义：`memory_records.user_authored`（区分用户写 vs 系统推断）、`supersedes_id`（可修订而非堆积）。版本化建议沿用同一套语义。

## 决策五 · 收集发生在当前窗口，不在首页（2026-10-06 追加）

**锁定规则**：用户不需要切换到首页去粘贴或填网址。收集动作必须能在 **300ms 内完成、不离开当前上下文**；整理永远延后到首页（决策三）。

即：

> **收集在用户工作的地方发生，整理在用户有空的时候发生。两者不在同一个时间点，也不在同一个界面。**

### 四条捕获入口（按摩擦从低到高）

| # | 入口 | 用户动作 | 工程就绪度 |
|---|---|---|---|
| 1 | **复制即收集** | **0 额外动作** —— 用户本来就在 Ctrl+C | 🟠 需补：剪贴板监听（Windows 用 `AddClipboardFormatListener`，事件驱动，优于轮询） |
| 2 | **全局热键** | 1 次按键 | 🟢 现成：`hotkey_win.rs` 已用 `RegisterHotKey`（WM_HOTKEY） |
| 3 | **拖入浮标** | 1 次拖拽 | 🟢 现成：`overlay_window.rs` 已有 lazy-create 透明置顶浮窗；`input_aim_calibrate.rs:152` 已有 `decorations(false)` + `set_always_on_top(true)` 全套先例 |
| 4 | **点击收取** | 1 次点击 | 🟢 现成：`tray.rs` 托盘菜单已有；`codex_micro_overlay.rs` 有置顶浮窗先例 |

补充事实：`tauri-plugin-autostart` 已装（`lib.rs:439`）→ 开机常驻可行，这是"托盘自动积累"能成立的前提。

### 网址不需要填
- 复制即收集已覆盖（复制地址栏 = 收下网址）。
- 实时读取浏览器当前 URL 目前**不可行**：`browser_bookmarks.rs` 只解析书签文件，无实时 URL 通道。替代方案（窗口标题解析 / UI Automation）成本高于收益，**建议不做**。

### 拖放的两个已知缺口
1. `tauri.conf.json` 未配置 dragDrop，Tauri 2 **默认关闭** webview 拖放 → 需显式开启并监听 `on_window_event`（`lib.rs:730` 已有事件入口）。
2. **拖到托盘图标**：Windows 需 Shell 拖放目标 COM，Tauri 不支持。→ 采用**常驻屏幕边缘浮标**作为接收靶心，这是最可控的方案。

### 隐私边界（沿用决策三）
复制即收集是摩擦最低的，也是**隐私风险最高**的：它必须落在「本地暂存」层，受目录白名单、应用排除列表、敏感字段过滤、自动过期约束，且**默认不能自动加入简报**。

原型：`docs/prototypes/onetone-capture-layer.html`（可点可拖：四条入口、浮标拖放、候选托盘、暂停感知、每次动作显示耗时与"未离开当前窗口"）。

## 决策六 · 右栏 = 发动机 + 目的地（2026-10-06 追加）

首页三栏的角色由两个比喻锁定：

- 左＝**乘客 / 原材料**：被运送、被引用；不产生动力，也不决定方向。
- 中＝**方向盘 / 锅**：用户唯一直接掌控的地方，写什么、先往哪走都在这里定。
- 右＝**发动机 + 目的地**：动力（通道 · 动作序列）与目标（发往谁 · 能收什么 · 到了没有）。

### 发动机舱（上）：动力是可绑定的，不是点一下就没了

| 元素 | 依据 |
|---|---|
| 怠速常驻（不打开首页也生效） | `tauri-plugin-autostart` 已装 · `lib.rs:439` |
| 动作序列 `runTargetSequence` | `agent/actions.rs:256`，已是现成的一等动作 |
| 通道绑定 chip | `ActionBindingView{ channel, trigger, enabled, risk, availability, source_storage }` · `binding_view.rs:12` |
| 前端消费 | `semantic-action-store.js` 已调用 `cmd_semantic_action_catalog` 并按通道取选项 |
| 摄像头整列划掉 | 只映射 6 个控制动作（`binding_view.rs:43`），零视频采集枚举 |

### 目的地（下）：目标是状态与事实，不是操作

| 元素 | 依据 |
|---|---|
| 当前车道 | `applied_lane() -> Option<(AgentKind, String)>` · `soft_pad_runtime/store.rs:110` |
| 容量（预算）归此块 | 换 Agent 就换分母：Codex 32k / Cursor 128k / Claude 200k |
| 路况（能力矩阵） | `focusComposer` ✓ · `openAgent` ✓ · `insert_text_no_enter` ✓ · 图片自动上传 × · 确认已发送 × |
| 到达回执 | 只报事实：已复制 / 已打开 / 已填入 / 发送状态未知 |
| 护栏（保护边界） | 随正文一起送出；违规检出 = git status 路径列表 ∩ guard |

### 三条推论

1. **预算属于目的地，不属于页面底部。** 容量是目标的属性，换目标就换分母；全仓库零 tokenizer，只能显示估算值。
2. **发动机不能自动驾驶。** 比喻的司机是用户，所以右栏不生成任何内容，只执行用户已经定好的方向 —— 这与"不引入 LLM"是同一条约束的两种表述。
3. **小白与高级的分界不在按钮数量，在是否接到发动机上。** 小白点方向盘上的按钮；高级用户把动作绑到通道（`runTargetSequence`），之后不必打开首页。

## 决策七 · 默认两栏：发送是动作，不是栏（2026-10-06 追加）

首页默认只有两栏：**左＝原料**（素材托盘，只读）· **中＝整理**（一整张纸）。第三栏不常驻。

投递相关内容降级为**发送抽屉**：由中栏底部的一条发送条触发（`发给 Codex · 2 项引用 ▸`），抽屉内才出现目的地、装载预算、待办、能力矩阵与回执。

### 原第三栏内容的去处

| 内容 | 去处 | 理由 |
|---|---|---|
| 通道状态 / 通道占用表 / 怠速 | **配置页** | 通道信息真正该出现的三个时刻是：动作结果回执、动作不可用的原因、配置页。首页常驻的是"绑定状态标签"，不是操作入口 |
| 动作序列 `runTargetSequence` | **配置页** | 配置一次、长期生效；首页只在动作完成后回执一次 |
| 常驻预算条 | **发送抽屉** | 写作时盯着容量条会让人在没写完时就开始删素材。预算属于"决定发的时候" |
| 目的地 / 能力矩阵 / 待办 | **发送抽屉** | 低频、一次性；用时才出现 |
| 保护边界 / 事实回执 | **发送抽屉** + 结果回来时 | 同上 |

### 附带的修正：决策二的"预算常驻"改为"发送时可见"

原决策二要求预算条常驻页面顶部或底部。改为：**写作期不显示，发送抽屉内显示**。理由不是省空间，而是常驻预算会改变写作行为（删素材以降容量），而容量问题只在投递时才真实存在。

### 让给 Agent 的，和不能让的

- **能让**：理解内容、出方案、执行改动 —— Agent 做得比 OneTone 好。
- **不能让**：**容量**（只有本机知道素材多大）、**送达**（只有本机知道有没有真填进去）、**溯源**（只有本机知道素材从哪来）。这三项让掉会静默失败：内容被截断而用户不知道为什么。

### 原型

`docs/prototypes/onetone-two-column-home.html`（左原料 + 中纸 + 底部发送条 → 抽屉；抽屉内换目的地会同时改变装载、待办与能力矩阵）。
