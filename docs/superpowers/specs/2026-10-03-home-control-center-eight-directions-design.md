# OneTone 桌面控制中心首页：八方向原型设计

日期：2026-10-03  
状态：已确认，待原型实施  
范围：独立 HTML 比较原型；不修改生产首页、配置或 IPC

## 1. 决策摘要

OneTone 新首页首先是**桌面控制中心**，其次帮助用户**发起工作**。在系统无法取得可靠事件、检查点或探针证据时，不把“继续工作”作为首页主线，也不伪造历史成果或任务进度。

本轮制作八个真正独立的首页方向：Vibe Coding、小白视图、Apple Vision Pro、Meta Quest 3、搜索引擎、Agent 聚合、Notion、Raycast。八个方向使用同一组 OneTone 状态与任务，以便比较信息架构，而不是比较内容多少或换肤效果。

原型用于回答：哪些方向可以融合，哪些方向应当舍弃。选型前不修改生产页面。

## 2. 产品目标

1. 用户打开首页后，能快速看懂当前桌面控制状态。
2. 用户可以从首页向目标应用或 Agent 发起一项工作。
3. 用户能知道语音、按键、Soft Pad、摄像头和 Agent Hook 是否可用。
4. 配置缺失时，首页说明具体缺口并提供可执行修复入口。
5. 八个方向必须在相同数据和状态下接受比较。
6. 原型应帮助提炼可融合元素，而不是过早选定一套完整视觉风格。

## 3. 非目标

1. 不在本轮替换生产首页。
2. 不读取或写入用户真实配置。
3. 不实现真实 Agent 调度、语音识别或跨应用注入。
4. 不展示无可靠来源的完成率、任务步骤、历史成果、额度或恢复点。
5. 不直接复制参考产品的商标、专有图标或像素级界面。
6. 不用八种配色包装同一套卡片布局。

## 4. 共同数据边界

### 4.1 可以展示

- 当前场景，例如编程、写作或会议。
- 当前输入目标，例如 Cursor、Codex、Claude 或 Notion。
- 四通道状态：语音、按键、Soft Pad、摄像头。
- Agent 状态：空闲、运行、等待用户、异常。
- 真实能力动作：开始听写、发起请求、选择目标、打开 Soft Pad。
- 修复动作：设置麦克风、确认目标、连接 Agent Hook。
- 当前原型会话中由用户交互产生的即时反馈。

### 4.2 禁止展示

- 没有事实源的百分比、阶段数或预计完成时间。
- 推断出来的“Agent 已经帮你完成了什么”。
- 不可靠的历史记录与恢复点。
- 假额度、假费用和假使用量。
- 对话正文或文件内容的猜测。

### 4.3 统一状态

八个方向必须支持相同的五种状态：

| 状态 | 事实 | 必须允许的动作 |
|---|---|---|
| 待命 | 通道与目标已准备，Agent 空闲 | 发起工作 |
| 正在倾听 | 麦克风可用，正在接收输入 | 暂停、结束、取消 |
| Agent 运行 | 已向明确目标发起请求 | 查看状态、停止或切换控制面 |
| 等待用户 | Agent 明确要求用户确认 | 查看并决定 |
| 配置缺失 | 麦克风、目标或 Hook 缺失 | 前往对应设置修复 |

`Agent 运行` 只表示可信的运行态，不展示推测进度。`等待用户` 只在 fixture 明确提供该状态时出现。

## 5. 共同任务

每个方向都必须能完成以下评审任务：

1. 判断当前工作场景和输入目标。
2. 判断四个触发通道中哪些可用。
3. 向一个 Agent 发起工作。
4. 在语音、文本或 Soft Pad 入口之间做出选择。
5. 识别 Agent 是否正在运行、等待用户或异常。
6. 在配置缺失状态中找到正确修复入口。
7. 返回待命状态，并知道下一步可以做什么。

## 6. 八个原型方向

### 6.1 Vibe Coding：工作流编排台

核心轴是**从想法到执行的线性编排**。中央主线为“描述目标 → 选择 Agent → 选择输入方式 → 执行”。通道状态作为每一步的可用性条件出现，而不是独立仪表盘。

- 主要优势：发起任务明确，适合 AI 编程。
- 主要代价：容易把 OneTone 限定为编程工具。
- 待验证融合元素：任务发起器、目标选择、执行前确认。

### 6.2 小白视图：唯一下一步

核心轴是**最低认知负担**。首页用人话回答“现在怎么样”和“你可以做什么”，首屏最多一个主动作。高级状态折叠到“看看为什么”。

- 主要优势：首次使用成本最低。
- 主要代价：高级能力发现和高频效率较弱。
- 待验证融合元素：人话状态、单一主动作、修复导向。

### 6.3 Apple Vision Pro：空间焦点

核心轴是**焦点对象与环境层级**。当前目标位于中央焦点层；场景、通道和 Agent 环绕其周围。未聚焦对象降低视觉权重，选择后进入前景。

- 主要优势：当前焦点和情境关系清楚，品牌辨识度高。
- 主要代价：桌面端可能形式大于效率。
- 待验证融合元素：焦点层级、背景降噪、上下文环绕。

### 6.4 Meta Quest 3：桌面驾驶舱

核心轴是**高可见度控制台**。页面横向组织为环境与设备、当前任务台、Agent 与动作，并支持专注模式与全局模式切换。

- 主要优势：桌面控制中心能力最强。
- 主要代价：信息密度高，对新用户压力较大。
- 待验证融合元素：设备健康区、模式切换、即时控制条。

### 6.5 搜索引擎：统一意图入口

核心轴是**通过意图召回能力**。首页以“你想让电脑做什么？”为中心，输入后分类召回 Agent、动作、场景、设置和修复入口。

- 主要优势：扩展性强，用户不必先理解信息架构。
- 主要代价：空输入框发现性不足。
- 待验证融合元素：统一意图入口、结果分类、示例查询。

### 6.6 Agent 聚合：多 Agent 指挥中心

核心轴是**以 Agent 为第一维度**。每个 Agent 展示可信连接状态、运行态和等待态，并共享一个发起入口与待处理队列。

- 主要优势：适合多 Agent 用户，协调价值突出。
- 主要代价：可能弱化 OneTone 的四通道能力。
- 待验证融合元素：Agent 状态带、目标选择器、等待队列。

### 6.7 Notion：模块化工作空间

核心轴是**可组织的信息块**。快速开始、当前场景、常用动作、Agent、输入方式和配置提醒构成可折叠工作区。原型展示组织方式，不实现完整块编辑器。

- 主要优势：清晰、可扩展、适合长期个性化。
- 主要代价：容易退化为卡片墙，实时控制感较弱。
- 待验证融合元素：可折叠分区、渐进展示、个性首页。

### 6.8 Raycast：命令优先启动器

核心轴是**键盘优先的即时动作**。默认焦点进入命令框，可搜索并执行听写、Agent 发起、场景切换、Soft Pad 和修复动作；下方展示建议与最近命令。

- 主要优势：专家效率最高，操作闭环短。
- 主要代价：发现性弱，依赖键盘习惯。
- 待验证融合元素：Command Palette、快捷动作、键盘导航。

## 7. 比较框架

原型提供固定评审栏，该评审栏不属于候选首页：

- 八个方向标签。
- 五种状态切换。
- 设计说明开关。
- 当前方向的核心思想、优势、代价和适用人群。
- 六项 1–5 分人工评分：小白易懂、发起效率、控制中心能力、状态可见性、扩展能力、OneTone 独特性。

评分保存在浏览器 `localStorage`。比较结果页汇总各方向评分、文字备注和候选融合元素，但不自动选出赢家。

评审时每次只全尺寸显示一个方向，禁止用缩略图并排代替真实尺寸体验。方向切换必须即时完成，不增加切换动画。

## 8. 视觉与交互约束

1. 八个方向保留中文界面、OneTone 名称和青绿色品牌信号，但不共用页面模板。
2. 每个方向必须在布局、导航方式、密度、主要动作位置和交互模型中至少三个维度上与其他方向不同。
3. 参考产品只贡献交互原则，不复制商标、专有资产或像素级外观。
4. 主验证尺寸为 `1280 × 800`，同时保证 `960 × 640` 可操作且无横向溢出。
5. 所有关键操作支持键盘焦点，状态不能只通过颜色表达。
6. 动效只用于焦点切换、状态反馈和面板展开；非用户触发动画保持克制，并尊重 `prefers-reduced-motion`。
7. 按钮必须产生可见结果；原型中不存在无响应的主操作。

## 9. 原型架构

原型位于独立目录：

```text
prototypes/home-control-center/
├── index.html
├── styles/
│   ├── shell.css
│   └── variants.css
├── scripts/
│   ├── app.js
│   ├── fixtures.js
│   └── evaluation.js
└── README.md
```

实现采用原生 HTML、CSS 和 JavaScript，可由静态服务器运行。比较外壳负责标签、状态和评分；每个方向只消费标准化 fixture 并发出原型动作事件。方向内部不得直接操作评分数据，也不得引用生产配置。

标准化输入：

```text
PrototypeSnapshot
├─ scene
├─ target
├─ channels[]
├─ agents[]
├─ attention
├─ configurationIssues[]
└─ availableActions[]
```

原型动作只改变内存中的演示状态并记录即时反馈。刷新后状态可以重置；评分和备注单独持久化。

## 10. 错误与空状态

- 数据缺失必须说明缺少什么，不使用泛化的“暂无数据”。
- 目标未确认时禁止显示“开始发送”，应先要求选择目标。
- 麦克风不可用时，语音入口保持可见但明确不可用，并提供设置动作。
- Agent Hook 不可用时，不推断 Agent 状态；允许继续使用非 Hook 能力。
- 浏览器不支持 `localStorage` 时，评分退化为当前会话内存保存，并显示说明。

## 11. 验证标准

### 11.1 自动检查

- 八个标签均可访问。
- 五种状态在八个方向中均可切换。
- 标签切换不丢失当前评审状态。
- 评分、备注和重载恢复符合预期。
- 不出现完成率、虚构额度或伪造历史文案。
- 主要操作均产生可见反馈。

### 11.2 浏览器检查

- 在 `1280 × 800` 和 `960 × 640` 检查八个方向。
- 逐一完成七项共同任务。
- 检查键盘导航、焦点可见性和减少动态效果。
- 检查控制台无错误。
- 为八个方向分别保存截图用于最终比较。

## 12. 完成定义

当八个方向均可在同一比较外壳中独立体验、完成共同任务、切换五种状态、记录评分与备注，并通过自动及浏览器检查时，本轮原型完成。随后由用户决定：

1. 保留哪些完整方向；
2. 从各方向抽取哪些融合元素；
3. 明确舍弃哪些模式；
4. 是否进入第二轮融合原型；
5. 最终是否规划生产首页集成。
