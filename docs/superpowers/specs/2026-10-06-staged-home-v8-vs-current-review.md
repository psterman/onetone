# 评估：`onetone-staged-home-v8.html` vs 现在线上的首页

- 日期：2026-10-06 22:50
- 评估对象：`docs/prototypes/onetone-staged-home-v8.html`（22:26，四步 Wizard：放材料 → 完成排版 → 看还缺什么 → 交给 Agent）
- 对照对象：线上真实首页（Tauri 应用 default 页，`src/index.html` `#homeZone` / `#homeWorkbench` + `src/js/features/home/*`）
- 结论一句话：**v8 回答的问题是对的，但它不应该"替换"现在首页，它应该成为第二个工位；并且在它自己的家族里，它已被 22:31 的 `onetone-staged-home.html` 部分取代 —— 正确做法是把两稿合并。**

---

## 0. 先说版本关系（容易被忽略）

同一晚原型链：`staged-home-v8`(22:26) → **`staged-home`(22:31，六态状态机)** → `staged-home-reviewed`(22:42)。

所以现在评估 v8，等于评估一个"已经被你自己改过一版"的方案。v8 剩下的独有资产是：**交付预览 Tab、每项素材的引用档位 + 保护锁、显式步骤条**。22:31 版独有的更强资产是：**COLLECTING 确认队列、通道条、选通道/交接双抽屉、单一状态机驱动**。二者是互补而非替代。

## 1. 现在的首页到底是什么（实勘，不是印象）

| 项 | 事实 |
|---|---|
| DOM 入口 | `src/index.html:188` `#homeZone` → `:189` `#homeWorkbench.is-v3` |
| 页头 | `#wbHomeAlerts` 告警条（`:192`）；Hero 直播球 `#wbHero` |
| Hero | 四模式：`voice` / `keys` / `softPad` / `camera`（`home-workbench.js:1787-1791` `renderHero`） |
| 状态物 | 检测 Pill（引擎/麦克风/延迟）、统计四格：**运行时长 / 操作次数 / 最常投递的 App / 最常按的快捷键**（`:1682-1697` `renderHeroStats`） |
| 告警 | 三类硬信号：上次崩溃（Rust watchdog 持久化）、识别引擎需修复（`model.repair`）、需初始化（`:326-380` `renderAlerts`） |
| 教学/配置 | `#wbHeroModeHint`、HowTo 抽屉（`home-workbench-panels.js:630`）、习惯 grid（`:1114`）、高级微调 `#homeAdvanced` |
| Agent 接触面 | **仅两处**：侧栏 `wbNavAgent` / `wbNavAgentData`（`:145/:149`）→ 跳到一个 iframe 原型页（`:4500-4505`）；SoftPad 里的 `AgentKind` 选择 |

**现在首页回答的问题是**："我马上能不能开口/动手，我的声音会被送到哪个 App、健不健康？"
**它的监视对象是本机输入链路**（麦克风在不在、引擎活不活、热键有没有冲突、上次是不是崩了）——**这是一套已经接线、有数据、有告警的真实系统。**

## 2. v8 换了第一性问题

v8 回答的是："我即将对 Agent 说的第一句话，够不够清楚？"

结构：左材料托盘 → 一张纸（标题 = 你的第一句原话 + 你的话 + 引用集）→ 通道 / 缺口 → 交给 Agent。

这不是"首页改版"，这是**换了一个工位**：从「用户 ↔ 输入法」换到「用户 ↔ 目标 Agent」。用术语说，现在首页是 **L1 控制面**，v8 是 **L0 简报面**。两者不需要互相替换，需要的是**工位分工**。

---

## 3. v8 相对"现在"的六个真进步（建议保留）

1. **通道从"绑定状态标签"变成"可点动作行"** —— v8:253-268 `engine` 区：`取消这一轮` + `Esc` / `说「取消」` / `小键盘·取消` / `摇头（摄像头没开）`。这补上了此前最刺眼的错配（首页主行只有控制词汇、监视缺位）：**纸上第一次出现了 Agent 的监视事实**（"Codex 改完了，在等你点头"）与能力缺口。
2. **预览由引用集编译，不再是手写副本** —— v8:409-419 `renderMd()` 从 `ITEMS.filter(used)` + `GUARDS` + `locked` + `#writing` 实时拼装。这直接修掉了两栏稿的 P0（预览 3 项 vs 底栏 2 项）。**正确性可验证，这是全稿最硬的一处。**
3. **预算诚实** —— v8:452-454："约 1.4k tokens · 上限查不到，不显示百分比"。对应"无 tokenizer → 必须标估算值"这条约束。（全仓 `is_exact` 恒 false，确无 tokenizer。）
4. **引用档位 + 保护锁可见可调** —— v8:359-363 / 392-395，每项素材 `连图带你写的话` / `只给标题和结构` / `只给路径` + `🔒 不许动`，即"素材只读、只能改你的话和引用方式"的雏形。
5. **把"没带上"说出口** —— v8:278-280 / 399-406：`左边还有 2 项没有带上…它们在等你决定`。沉默才是监控类产品的敌人。
6. **交付责任分栏诚实** —— v8:318-337：抽屉分「OneTone 将会 / 还需要你」，回执含 `还没传，等你` 与 `不知道`。命中事实口径命门：`insert_text_no_enter` 不发 Enter，**"已填入" ≠ "已发送"**。

## 4. 六个问题（前三个是 P0）

### P0-1 落地差距被严重低估（这是"替换首页"的最大风险）
实勘：全仓 `grep -rn "cmd_material|fn cmd_brief|materials"` **零命中**；`pub fn cmd_*` 共 259 个，**没有一个素材/简报 IPC**；`agent_memory` 现有 6 张表里没有 materials / briefs。
同时缺口确认：拖放 🔴（无 fileDropEnabled / `WM_DROPFILES`）、截图 🔴（全仓零实现）、tokenizer 🔴、剪贴板监听 🟠（尚无 `AddClipboardFormatListener`）。
→ 现在首页是**已接线 + 有数据 + 有告警**的真系统；v8 目前是**没有任何后端**的构想。若用它替换首页，第一步是删掉用户现在唯一的健康面：**"识别引擎坏了谁知道？"**

### P0-2 加素材 = 正文被藏（Wizard 特有的、比 22:31 版更狠的形态）
v8:488-495 每次 `data-add` 都 `ITEMS.push(...)` 后 `setStage(1)`；而 429-430 在 `n===1` 时把整个 `#grown`（含 `#writing` 用户正文）`display:none`。
→ 用户写完一段话，再放一个文件，字就没了。这是纸不该有的行为：**纸永远不会被合上。**

### P0-3 三套"我在哪"的指示互相打架
顶部步骤条（v8:196-201，**`span` 不可点**）+ `编辑 / 交付预览` Tab（230-233）+ 底栏主行动按钮（299-302）。
既显示进度又不许回退，比 22:31 版更糟 —— 那一版至少用单一 `data-state` 驱动全部 UI。状态机的代价是**不可逆**；Wizard 把它做成了**明示却不可逆**，最难受的组合。

### 其余（P1）
4. **缺素材溯源三件套**：只有 `data-t` tooltip（v8:378），无 来源 / 采集时间 / 内容指纹 / 可否回跳，违反约束 1。
5. **缺简报身份与版本**：无 名称 / 版本 / 投递次数 / 差异比对；自动保存只是页头一句静态"已保存到本地"（v8:202），违反约束 4。
6. **缺候选/已用分流与感知开关**：无「● 正在感知 …」、暂停、清空、目录白名单、敏感过滤，违反约束 3。左栏的 `pending` 小黄点（65-66）只是装饰，没有对应的决策席位。
7. 次要：步骤标签动词/名词混排（放材料 / 完成排版 / 看还缺什么 / 交给 Agent）；`.item` 是可点 `div`，无 role / tabindex。

## 5. 裁决与建议

**不要替换首页，把它做成为第二个工位。**

- 工位 A（现在首页，改名「输入」）：保留全部，尤其是告警条与四格统计 —— 它是唯一回答"语音还能不能用"的地方。
- 工位 B（v8 演进版）：`我 → Agent` 的首次沟通准备台。
- 若二者必须共屏，最小代价是把 A 的**告警 + 健康状态压成一条压缩条**，挂在 B 的页头或页脚；不要试图让 B 承载健康监控。

**进 B 之前必须补的三件事**（按优先级）：
1. 可逆：去除 `setStage(1)` 回退逻辑；步骤条改为可点或干脆去掉，**保留 22:31 的单一状态驱动**。
2. 「加素材不动纸」：任何 stage 下 `#writing` 永不隐藏。
3. 先做一个**只有一项素材也能跑通**的后端切片（materials 表 + 引用档位 + 编译式预览），而不是先把 UI 铺满。

**合并稿走法（推荐）**：取 **22:31 的状态机骨架**（EMPTY / COLLECTING / ASSEMBLED / CHANNEL_SELECTED / HANDING_OFF / HANDED_OFF + 单主按钮 + 通道条 + 双抽屉），把 **v8 的三件资产移植进去**：① 编译式交付预览 ② 每项素材的引用档位 + 保护锁 ③ 纸上的那条「engine 通道 + 缺口」行。理由：22:31 版流程更干净，v8 内容正确性更强，两者叠加即是当前最优。

## 6. 判定门槛（何时才配谈"替换首页"）

- [ ] `materials` 表 + 溯源三件套（来源/时间/指纹/回跳）落库，至少 `past` 1 项真实素材端到端跑通
- [ ] 编译式预览 == 引用集（渲染同一数据源，**禁止第二份内容源**）
- [ ] 回执能区分"已填入 / 用户确认已发送 / 未知"，且默认诚实显示未知
- [ ] 首屏 3 秒内不需要读任何说明就能知道下一步做什么（现在首页的达标点是那个直播球）
- [ ] 输入健康告警在 B 里仍有可见出口
