# OneTone 首页 Now 架构设计

## 1. 背景与问题

上一轮四个首页原型分别落成了旧首页、LLM 聊天入口、动作卡片墙和信息驾驶舱。它们虽然布局不同，但共同把 OneTone 的内部能力直接搬到了首页，导致首页无法回答最重要的问题：用户此刻是否需要 OneTone 做什么。

OneTone 的独特价值不是再提供一个聊天框，而是把前台应用、项目、Agent 状态、输入节奏和四种通道合成为一层低打扰的协作体验。首页应当展示“当前情境 + OneTone 正在提供的帮助”，而不是展示所有数据来源和功能入口。

## 2. 设计目标

1. 首页默认安静陪伴：没有待处理事项时，不主动制造任务或按钮。
2. 只有真实且有帮助的数据才进入首页；推测不得伪装成事实。
3. Agent 等待用户介入时，页面只突出一个最重要事项。
4. 历史、项目记忆、链接与数据、设置不再形成首页标签墙。
5. 语音、按键、Soft Pad、摄像头作为触发和证据通道存在，不成为四个并列功能区。
6. 面向低认知负担的桌面体验：连续画布、留白、明确层次、少卡片、少状态噪音。

## 3. 非目标

1. 不在首页建立新的 LLM 对话窗口。
2. 不在首页展示完整历史、完整项目记忆或所有数据源。
3. 不显示推算百分比、未经验证的 Agent 进度或虚构的任务状态。
4. 不把摄像头状态作为首页主内容，也不允许摄像头单独批准高风险动作。
5. 不把原型中的事件模型直接当作生产持久化实现。

## 4. 全局信息架构

一级入口缩减为三个：

| 入口 | 责任 | 首页关系 |
|---|---|---|
| 现在 | 当前情境与正在提供的帮助 | 默认首页 |
| 我的习惯 | 情景、语义动作与四通道绑定 | 独立配置页 |
| 设置 | 设备、隐私、数据源、Agent 接入与诊断 | 独立配置页 |

以下内容不再占用一级导航：

- 历史：从当前情境或活动入口按需打开。
- 项目记忆：从当前项目、恢复摘要或判断依据进入。
- 链接与数据：归入设置；首页只保留“查看判断依据”。
- Agent：作为当前情境的一部分显示，不单独成为首页标签。
- 动作与入口：归入“我的习惯”，不在首页平铺。

首页和二级页之间必须保留可预测的返回路径；二级内容不通过首页卡片网格预先展开。

## 5. 首页核心模型

首页消费已经完成仲裁的 `HomeSnapshot`，UI 不直接读取 Provider 私有数据，也不在渲染层猜测情境。

```text
HomeSnapshot
├─ mode: quiet | attention | return | degraded
├─ updatedAt
├─ context
│  ├─ app
│  ├─ project
│  ├─ provider
│  ├─ session
│  ├─ source
│  └─ freshness
├─ headline
├─ assistance
├─ attention
├─ continuation
├─ progress
├─ evidence
└─ channels
```

字段约束：

- `headline`：当前情境的一句话，最多两行，必须能追溯到 `context` 或用户明确创建的 session。
- `assistance`：解释 OneTone 正在提供的实际帮助，例如保持其他提醒安静、把输入路由到当前 Agent、等待用户确认。
- `attention`：只有明确需要用户介入时才存在；同一时刻最多一个主事项。
- `continuation`：只有存在可靠 session、checkpoint 或最近事件时才存在。
- `progress`：默认为空，必须通过数据准入规则后才允许出现。
- `evidence`：判断依据和来源，默认收起。
- `channels`：通道能力和触发结果，供交互层使用，不直接形成首页模块。

## 6. 首页模式与状态转换

### 6.1 quiet：安静陪伴

可靠上下文存在，但没有需要用户处理的事项。

示例：

> 你正在 Cursor 中处理 voice-pilot。  
> 我会保持其他提醒安静。

此模式没有主按钮，不展示任务卡片或建议列表。

### 6.2 attention：需要处理

Agent 正在等待批准、回复、失败处理或其他明确决定。

示例：

> Claude 正等你确认文件修改。

只展示一个主动作，例如“查看并决定”。其他待处理事项只能以可展开的数量提示存在。

### 6.3 return：回到工作

用户重新打开 OneTone，且存在可靠的 session 或 checkpoint。

示例：

> 你上次停在首页架构设计。  
> 当前项目仍是 voice-pilot。

只展示一个“继续上次工作”入口。

### 6.4 degraded：依据不足

无法确认当前项目、Agent 或 session 时，首页必须说明原因和恢复路径。

示例：

> 我暂时无法确认你正在处理的项目。

禁止用空卡片、假数据或泛化的“暂无内容”代替原因。

### 6.5 转换规则

```text
可靠上下文
   ├─ 无待处理事项 ──→ quiet
   ├─ 有明确待处理事项 → attention
   └─ 有恢复点且用户刚回来 → return

无法建立可靠上下文 ─→ degraded

attention 完成 ─────→ quiet

progress 过期 ──────→ 保留 headline，隐藏 progress
```

状态变化必须稳定，不能因单次前台抖动或单帧摄像头信号频繁切换首页模式。

## 7. 精准进程数据准入

只有同时满足以下条件，`progress` 才能进入首页：

1. 来源是 Provider 原生事件、真实 session 或 checkpoint。
2. 能明确关联当前项目和当前 Agent。
3. 有明确更新时间。
4. 仍处于可接受的新鲜度范围。
5. 能帮助用户做出下一步决定。

允许：

> 首页架构 · 已确认信息层级 · 2 分钟前

不允许：

> 已完成 68%

除非 Agent 原生提供了真实、结构化、可解释的进度。数据过期时隐藏进程但保留已知上下文；读取失败时不能覆盖已有历史。

## 8. 四通道边界

```text
语音       → 开始听写、发送、确认
按键       → 快捷执行和确认
Soft Pad   → 低摩擦入口和状态反馈
摄像头     → 上下文证据或发起请求
```

通道触发后只产生短暂、可理解的反馈，例如“已通过 Soft Pad 继续 Cursor”，不在首页留下通道控制面板。

摄像头不能单独改变高风险动作的最终状态。它可以贡献 Presence、Attention 或 Gesture 证据，但高风险批准必须通过第二通道确认。

## 9. UI 方向

### 9.1 结构

所有模式共用一套连续画布：

1. 当前情境：一个主标题，最多两行。
2. 正在帮助：一段清晰的结果说明。
3. 精准进程：满足准入条件时，以内联文字或细线出现。
4. 判断依据：默认收起，按需查看。
5. 需要处理时，最多出现一个主按钮。

不使用卡片栅格、左右双栏、永久聊天输入框或统计仪表盘。

### 9.2 视觉

- 暖白或低饱和深色背景，深蓝文字，青绿色作为主要强调色。
- 通过字号、留白和位置建立层级，减少边框、阴影和密集标签。
- 主标题约 28–32px，正文不低于 16px，辅助信息 13–14px。
- 不使用 AI 渐变光球、持续发光或装饰性循环动画。
- 动画只表达状态变化，支持 `prefers-reduced-motion`。
- 所有关键操作保留清晰文字、键盘路径和可见焦点。

“面向女性用户”在本设计中解释为低压、易读、温和、有呼吸感的体验，不等同于粉色、可爱或装饰化。

## 10. 原型比较约束

下一轮四个 HTML 原型不再比较四种页面布局，而比较四种首页行为表达：

1. 同一安静陪伴架构下，比较不同的情境表达方式。
2. 同一 attention 接管规则下，比较用户如何理解“需要我处理”。
3. 同一 progress 准入规则下，比较精准数据出现时的视觉权重。
4. 同一全局导航下，比较二级信息如何被按需召回。

四个原型都必须通过 quiet、attention、return、degraded 四种状态；不得再出现卡片墙、聊天首页、双栏驾驶舱或四通道并列面板。

## 11. 验收标准

1. quiet 状态没有主按钮，也没有虚构建议。
2. attention 状态只有一个主事项和一个主动作。
3. progress 缺失时不出现空图表、空卡片或假百分比。
4. degraded 状态说明原因，并提供恢复路径。
5. 历史、项目记忆、链接与数据、设置不再作为首页一级标签墙。
6. 四通道不以四个功能区出现在首页。
7. 摄像头不能独立完成高风险批准。
8. 640×680 窗口不出现横向溢出，键盘操作和焦点路径可用。
9. 原型只服务于架构比较，不被当作生产持久化或 Provider 数据实现。

## 12. 后续阶段
