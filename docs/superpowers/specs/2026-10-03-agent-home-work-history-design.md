# OneTone Agent 工作记录首页架构设计

日期：2026-10-03  
状态：待用户审阅  
范围：Agent 首页的信息架构、数据边界、状态模型、视觉层级与原型方向  
约束：本阶段只定义架构与原型验收标准，不修改生产代码

## 1. 定位

新的首页不是 OneTone 的第二套应用壳，也不是独立的“现在 / 我的习惯 / 设置”产品。

它的唯一定位是：

> 现有左侧 Agent 入口下的 Agent 工作记录首页。

页面要回答三个问题：

1. Agent 最近替用户做了什么？
2. 当前工作停在哪里，用户下一步是否需要处理？
3. 用户下次回来，能否快速找到并继续这项工作？

因此，“历史记录”不是一个需要另开标签的附属功能，而是 Agent 首页的主内容；“当前工作”与“恢复工作”是历史记录的两个重点视图。

## 2. 现有应用边界与依据

当前产品已经有全局左侧导航，且其中已经存在：

- Agent：Agent 工作入口；
- 数据：Agent 数据、诊断和来源查看入口；
- 我的习惯：已有的习惯配置入口；
- 按键设置、语音设置、摄像头等 OneTone 能力入口；
- 通用设置、声音与反馈等软件级设置入口；
- 全局功能或设置搜索。

这意味着新首页不能再创建一组平行的顶部导航，也不能把既有入口改名后重复呈现。左侧导航是全局信息架构的唯一来源，新页面只负责 Agent 这一入口内部的工作记录与当前工作状态。

## 3. 目标与非目标

### 目标

1. 让 Agent 的历史、当前会话、暂停点和恢复动作在同一个连续工作区内可见。
2. 让用户明确区分“Agent 正在处理什么”和“OneTone 软件怎么配置”。
3. 只有存在真实来源时才展示项目、前台应用、Agent、会话和判断依据；未知信息明确显示未知，不用默认值伪装。
4. 安静模式仍然保留工作记录、上下文和最近活动；安静只表示不主动打扰，不表示页面空白。
5. 正在倾听时，实时识别文字必须是主要反馈，不得只显示一个“倾听中”按钮。
6. 页面在窄窗口中仍有明确主线，不依靠大量卡片填充空间。

### 非目标

- 不在 Agent 首页复制“我的习惯”。
- 不在 Agent 首页复制 OneTone 的软件设置。
- 不把“连接与数据”做成首页主要模块；它属于来源、诊断和数据入口。
- 不把首页做成 LLM 对话页、聊天记录页或卡片仪表盘。
- 不展示未被真实数据支持的 Agent 进度、完成率、智能建议或快捷键。

## 4. 信息架构

```text
OneTone 左侧全局导航
└── Agent（选中）
    └── Agent 工作记录首页
        ├── 当前工作上下文
        ├── 需要用户注意的事项（有才显示）
        ├── 最近工作记录 / 会话时间线
        ├── 当前项目与恢复点（有依据才显示）
        ├── 判断依据（按需展开）
        ├── Agent 设置（上下文动作，不是全局设置）
        └── 实时倾听栏（仅倾听时出现）
```

左侧全局导航仍然负责：Agent、数据、我的习惯、按键设置、语音设置以及软件设置。首页不再出现“现在 / 我的习惯 / 设置”这组本地标签。

## 5. 页面结构

### 5.1 页面头部：当前工作身份

头部只表达当前 Agent 工作身份，不做品牌欢迎页：

```text
Agent
Cursor · voice-pilot
当前会话：今天 14:32 开始 · 进行中 / 已暂停 / 已结束
```

项目、前台应用、Agent 名称和会话状态均来自快照。缺少哪一项就隐藏该项或显示“未确认”，不能用固定文案填充。

头部动作最多保留一个主要动作，例如“继续工作”或“查看会话”；其余动作使用次级按钮或溢出菜单。

### 5.2 当前工作与注意事项

这是页面顶部的工作状态区，不是泛化的 AI 建议卡片。只展示用户现在需要知道的事实：

- Agent 最近一次实际动作；
- 当前会话是否等待用户；
- 是否存在可恢复的检查点；
- 是否发生需要用户确认的项目切换、输入目标变化或来源不确定。

没有待处理事项时，这一段可以收缩成一句状态，不制造空任务。

### 5.3 工作记录时间线

历史是首页主区域，采用连续的时间线而非多个卡片网格。每条记录包含：

- 时间；
- 来源应用 / 项目 / Agent；
- 用户输入或 Agent 行为的简短摘要；
- 结果：完成、暂停、等待用户、失败或仅记录；
- 可执行动作：继续、查看详情、重新打开项目。

时间线至少显示最近几条真实记录，并提供“查看全部 Agent 记录”入口跳转到既有 Agent 数据/历史入口。没有记录时要说明“还没有 Agent 工作记录”，同时提供一个真实可执行的开始入口，而不是渲染空白卡片。

### 5.4 项目上下文与恢复点

项目记忆不作为独立首页标签。只有当当前会话存在项目和恢复点时，在时间线附近显示一个轻量上下文段：

```text
上次停在
voice-pilot · Agent 会话 14:32
已完成：确认首页定位
待继续：整理历史记录的呈现方式
[继续这项工作]
```

这段内容服务于“回来继续工作”，而不是展示所有记忆。完整项目记忆进入 Agent 数据或会话详情。

### 5.5 判断依据

“查看判断依据”不能再是原始键值表。展开后使用可读的来源链：

```text
前台应用 Cursor
      ↓
工作区 voice-pilot
      ↓
当前 Agent Cursor
      ↓
输入优先发送到 Cursor
```

每个节点显示来源、更新时间和状态标签：已确认 / 推断 / 不可用。链条底部说明“这条依据影响了什么”，例如“决定本次输入发送到 Cursor”。原始字段和诊断信息仍放在左侧“数据”入口。

### 5.6 实时倾听栏

只有正在倾听时才显示底部实时栏，并使用整页底部的稳定区域：

```text
正在倾听 · Cursor
“我想把首页的历史记录放到主区域……”
实时识别中……
[暂停] [结束并查看] [取消]
快捷键：Ctrl+Shift+D
```

快捷键必须读取真实配置；没有配置时显示“快捷键未设置”，不得硬编码一个无效快捷键。实时文本应持续更新，结束后进入一条新的 Agent 工作记录或待确认草稿。未倾听时，右下角只保留真实存在的全局入口或隐藏，不显示无效的“倾听中”假状态。

## 6. 状态模型

首页至少支持四种数据状态，但它们共享同一信息架构：

| 状态 | 视觉重点 | 必须保留 |
|---|---|---|
| 安静 quiet | 当前身份与最近记录 | 历史、项目、来源状态 |
| 需要注意 attention | 一条需要用户处理的事项 | 历史和上下文 |
| 返回工作 return | 上次停点与继续动作 | 最近会话记录 |
| 数据受限 degraded | 缺失原因与可恢复动作 | 已知的历史，不伪造未知数据 |

安静模式不能通过大面积空白表达。数据受限时要区分“尚未获取”“来源不可用”“尚未确认”和“确实没有记录”。

## 7. 数据契约方向

页面消费一个统一的 `AgentHomeSnapshot`，而不是从多个 UI 组件各自猜测状态：

```text
AgentHomeSnapshot {
  currentProject
  activeSession
  attention
  recentEvents[]
  recentSessions[]
  resumeCheckpoint
  contextEvidence[]
  inputState
  agentSettingsSummary
  freshness
}
```

每个字段必须带有来源、时间和可信度或可用性状态。页面只对真实快照做呈现，不能因为组件需要内容而创建假数据。

数据职责边界：

- Agent 首页：当前工作、工作记录、恢复点、与当前判断相关的上下文；
- Agent 数据入口：完整历史、原始事件、诊断、连接和数据源；
- 我的习惯：用户行为偏好、场景规则和绑定关系；
- OneTone 设置：按键、语音、摄像头、声音、通用设置等软件配置；
- Agent 设置：当前 Agent 的提供方、目标和 Agent 特有行为，作为 Agent 页面内的次级动作进入。

## 8. 视觉与交互原则

1. 保留现有 OneTone 左侧导航，不另起一套顶部应用导航。
2. 主线只有一条：当前工作身份 → 需要注意 → 工作记录 → 恢复动作。
3. 时间线优先于卡片；能用连续内容表达，就不拆成卡片墙。
4. 右侧空间用于上下文、来源链或详情，不放无关的连接状态和装饰性统计。
5. 首屏最多一个主要 CTA；次级动作靠近对应记录或通过溢出菜单呈现。
6. 不使用泛化的 AI 光晕、机器人装饰、无依据的百分比和“智能建议”占位。
7. 重要状态依赖文字与结构，不只依赖颜色或图标。
8. 文字和按钮必须描述真实动作；无效快捷键、无效入口和虚假的实时状态不得出现。

## 9. 原型比较方向

下一步原型仍做四个，但比较的是同一 Agent 工作记录架构下的主次关系，而不是四套孤立产品壳：

1. **时间线优先**：最近工作记录占最大视觉权重，适合高频回看和追溯。
2. **当前会话优先**：当前工作与实时状态占最大权重，历史作为连续记录承接。
3. **恢复工作优先**：围绕“上次停在哪里、现在继续什么”组织首屏。
4. **待处理优先**：先突出确实需要用户处理的事项，无事项时自然回到历史时间线。

四个原型必须共用：现有左侧 Agent 入口、时间线历史、项目/会话身份、判断依据展开、真实快捷键占位和实时倾听栏。不得再次加入“我的习惯”“设置”“连接与数据”三个重复一级入口。

## 10. 验收标准

- 用户能从现有左侧导航明确知道自己在 Agent 入口内，而不是进入了另一个应用。
- 首屏不空白，且第一眼能看见当前 Agent 工作身份与最近工作记录。
- 用户不需要进入单独的“历史”标签即可看到最近记录。
- “我的习惯”和 OneTone 设置不会在首页重复出现。
- Agent 设置与软件设置有明确名称、位置和职责边界。
- 判断依据能看懂来源链，并知道它影响了什么。
- 倾听时能看到实时文字、真实控制动作和真实快捷键；未倾听时不显示假状态。
- 没有数据时能看见缺失原因和下一步，而不是大片空白或默认数据。
- 页面没有与当前 Agent 工作无关的连接与数据主模块。
- 四个原型能比较优先级与交互行为，最终可选出一个进入实现规划。
