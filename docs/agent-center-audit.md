# 首页「Agent 中心改造」评估报告

> 评估对象：`output/agent-console-home.html`（v1）  
> 评估日期：2026-10-04 ｜ 结论：**未完成。完成度 ≈ 12.5%（1.5 / 12 分）**  
> 定性：v1 是 **Attention Center（注意力中心）**，不是 **Agent Center（agent 中心）**

---

## 一、判定标准：什么是"agent 中心"

"整合各 agent 信息、不用打开 agent 就能操作"要成立，agent 必须是**一等公民**，而不是别人卡片上的装饰标签。据此定 6 条硬判据：

| #      | 判据               | 合格标准                                 |
| ------ | ---------------- | ------------------------------------ |
| **A1** | Agent 是一等实体      | 有独立的卡片/列表项，能承载自身的状态、指标、操作入口          |
| **A2** | Agent 级状态可见      | 安装状态、版本、数据路径、健康度、配额/限流               |
| **A3** | Agent 级操作可达      | 启动 / 续跑 / 配置 / 装 hook / 导出 / 归档 / 禁用 |
| **A4** | Agent 级指标聚合      | 会话数、成本、成功率、平均时长——以 agent 为维度汇总       |
| **A5** | Agent 级洞察        | 能回答"擅长什么 / 最近在干嘛 / 该不该换一个"           |
| **A6** | 未接入 agent 可见且可解释 | 装了但接不上的 agent 也要出现，说明原因与替代方案         |

## 三、根因诊断：三个结构性错位

### 1. 组织维度错位 —— 按"事件"组织，而非按"实体"组织

v1 的第一屏分区是：`运行中` → `需要你` → `时间线` → `成本` → `项目` → `记忆`。  
这是**事件流 / 注意力流**的切法（我上一轮刻意这么设计，理由是"实时态是竞品空白"）。  
但用户要看的&#x662F;**"我有哪几个 agent、它们各自什么情况"**——这是**实体清单**的切法。

两者不矛盾，但主次错了：**agent 清单应该是骨架，事件流是挂在骨架上的血肉**。  
v1 把血肉当骨架，agent 退化成了血型标签。

### 2. 操作对象错位 —— 按钮都指向"会话"，没有指向"agent"

| v1 的按钮                | 作用对象                    |
| --------------------- | ----------------------- |
| 查看实时输出 / 接管终端 / 中断    | 会话                      |
| 建议 compact            | 会话                      |
| 续跑 ▸                  | **项目**（还会弹出"选哪个 agent"） |
| 生成 CLAUDE.md / 复制上下文包 | 项目                      |

**缺的是**：升级 agent、装 hook、切模型、配置数据路径、导出该 agent 全量历史、设置归档策略、禁用某个源。  
"不用打开 agent 就能操作"这句需求，v1 只满足了"看"，没满足"操作"。

### 3. 覆盖度错位 —— 只显示能接的，隐藏接不了的

本机实勘到 **12 个 agent 目录**，v1 首页只出现 4 个（Claude / Codex / Cursor / WorkBuddy）+ Trae 一个灰 chip。  
MiniMax、Hermes、OpenClaw、Marvis、Gemini CLI、Antigravity、Qoder **全部不可见**。  
用户无法回答"我装了这么多，到底哪些能用"——而这正是聚合类工具最该回答的第一个问题。

## 四、改造方案（v2）

### 4.1 结构变更：双视图，Agent 中心为默认

```
[指挥台] [Agent 中心 ●默认]        ← 顶栏下新增 Tab
```

| 视图                 | 定位                                   | 保留 v1 的什么   |
| ------------------ | ------------------------------------ | ----------- |
| **Agent 中心**（新，默认） | 以 agent 为骨架：全量 agent 清单 + 各自状态/指标/操作 | —           |
| **指挥台**（原 v1）      | 以事件为骨架：运行中 / 需要你 / 时间线 / 项目          | 全部保留，作为第二视图 |

之所以保留双视图而非替换：上一轮论证的"实时态是竞品空白"依然成立，两个视图互补而非互斥。

### 4.2 Agent 中心分区（逐条补判据）

| 区                   | 补哪条      | 内容                                                                                                                 |
| ------------------- | -------- | ------------------------------------------------------------------------------------------------------------------ |
| **① 已接入 Agent 网格**  | A1 A2 A4 | 每 agent 一张大卡：状态灯 + 名称 + **版本** + 形态(CLI/IDE/桌面) + 数据路径 + 今日会话/成本/**成功率**/均时 + 24h 活跃迷你条 + 告警徽标                     |
| **② Per-agent 操作条** | A3       | 卡片底部按钮行：`续跑` `打开` `配置` `⋯`（装 hook / 切模型 / 导出历史 / 归档策略 / 限流设置 / 禁用该源）                                               |
| **③ Agent 对比表**     | A5       | 6 个 agent × 7 维度（接入难度 / 单次成本 / 均时 / 成功率 / **数据完整性** / **实时感知** / 最适合场景）—— 直接回答"该用哪个"                               |
| **④ 未接入 / 受限区**     | A6       | Trae(加密) / MiniMax / Hermes / OpenClaw / Marvis / Gemini CLI / Kimi → 每个标注**原因** + **当前能给什么** + `请求支持` / `重新探测` 按钮 |

### 4.3 Per-agent 卡必须包含的 6 个字段（A2 硬性要求）

```
状态灯 · 名称 · 版本 · 形态 · 数据路径 · 最近同步时间
```

其中**版本 + 数据路径**是 v1 完全缺失且运维价值最高的两项：

- 版本决定 adapter 兼容性（Cursor 3.0 / 3.16 的 key 位置就不同）
- 路径让用户能自己核验"你读的到底是不是我那个目录"

### 4.4 数据完整性分级（补齐 A5）

把上一轮的可得性矩阵**产品化**到 UI 上，而不是只躺在文档里：

| 等级      | 含义                | 本机实例                                  |
| ------- | ----------------- | ------------------------------------- |
| **完整**  | 对话 + 用量 + 时间戳全可解析 | Claude / Codex / WorkBuddy            |
| **受限**  | 可读但需限流或版本探测       | Cursor(7.6GB) / Qoder                 |
| **仅提问** | 只有用户输入，无回答        | Trae 旧版                               |
| **不可读** | 加密或未落盘            | Trae 新版 / MiniMax / Hermes / OpenClaw |

## 六、落地建议

1. **v2 原型已产出**：`output/agent-console-home-v2.html`（双视图，Agent 中心默认）。
2. **数据字段全部来自本机实勘**，不是占位符：Claude 2.1.288 / Codex 0.160.0 / WorkBuddy 2.147.0 / Cursor 7.6GB / Qoder `main.sqlite` 0.88MB / Trae SQLCipher。
3. **下一步工程化**：把 Per-agent 卡的 6 个字段固化为 `AgentRegistry` 表（id / name / kind / version / dataPath / capability / lastSync），由 `probe-agent-dbs.py` 的探测结果直接填充——**这张表就是 agent 中心的后端骨架**，v1 缺的就是它。
