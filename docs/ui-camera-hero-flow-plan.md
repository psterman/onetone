# 摄像头 Hero 流程规划

## 核心定位

摄像头页不应继续停留在“设备预览 / 调试”页，而应升级为当前习惯的第三种输入通道：

`视觉触发 -> 执行动作 -> 视线管理`

其中“视觉触发”负责识别用户的刻意行为，“执行动作”把视觉信号翻译成语音意图，“视线管理”负责区域级确认、取消、发送等收尾补充。

## Hero 总布局

推荐 hero 区域使用三段式，但不要照搬按键页的“触发 / 激活 / 收尾”命名：

1. `视觉触发`
   - 展示当前摄像头状态、人脸状态、最近识别到的动作。
   - 主要控件：离席 / 回席、摇头、长眨 / 双眨、五指 / OK / V、多人人脸。
   - 每个触发项应有开关、灵敏度、保持时长、冷却时间。

2. `执行动作`
   - 选中某个视觉触发后，在这里绑定语义动作。
   - 动作不要先暴露快捷键，而是展示用户能理解的语音意图。
   - 推荐动作：语音输入法激活、语音确认、语音发送、语音取消、暂停语音、恢复语音、隐私屏。

3. `视线管理`
   - 使用 3x3 或粗区域识别，不把视线当精确鼠标。
   - 支持“看向区域 + 停留 + 手势/眨眼确认”的组合动作。
   - 适合放在收尾阶段：看发送区进入确认，OK 或长眨完成发送，摇头取消。

## MVP 优先级

### 第一批必须做

- 离席 -> 暂停语音 / 隐私屏
- 回席 -> 恢复语音 / 关闭隐私屏
- 摇头 -> 语音取消
- 长眨 -> 激活语音或确认
- 多人出现 -> 暂停监听 / 隐私保护

这些动作识别稳定、语义自然、误触成本低。

### 第二批可做

- OK 手势 -> 确认
- 五指摊开 -> 暂停 / 等一下
- 握拳 -> 取消
- 双眨 -> 发送确认
- 视线右下停留 -> 进入发送确认

这些动作需要“保持 0.8-1.5 秒 + 倒计时反馈”。

### 暂缓

- V 手势切换模式
- 桌面物品检测
- 手机 / 杯子识别
- 托腮、握拳等情绪解释
- 精确读唇、网站识别、代码内容识别

这些容易不稳定，或容易造成监控感。

## 交互规则

### 视觉触发

- 默认只开离席 / 回席和摇头取消。
- 手势类默认关闭，作为“实验”入口。
- 每个视觉触发必须能单独关闭。
- 每个触发必须显示最后一次识别状态，如“刚刚识别到 OK，未执行，因为不在确认状态”。

### 执行动作

动作按风险分级：

- 低风险：取消、暂停、隐私屏，可以直接执行。
- 中风险：激活、确认，需要稳定保持。
- 高风险：发送、提交，必须二次确认。

不要让“发送”成为单一视觉动作的默认结果。推荐流程：

`看向发送区 -> 进入确认 -> OK / 长眨 -> 发送`

### 视线管理

- 未校准时只显示粗区域：左 / 中 / 右 / 上 / 下。
- 校准后显示 3x3 区域和停留进度。
- 视线只表达“我可能在看哪个区域”，不表达精确点击。
- 发送、删除、覆盖类动作必须叠加手势或眨眼确认。

## 习惯界面接入

在习惯页中，摄像头不应作为孤立配置，而应作为“输入通道”出现：

- 顶部增加通道状态：按键、语音、摄像头。
- 当前习惯摘要中增加视觉触发摘要：
  - `离席暂停`
  - `摇头取消`
  - `OK 确认`
  - `视线发送确认`
- 场景模板区增加摄像头模板：
  - `离席隐私`
  - `手势收尾`
  - `视线确认发送`
  - `同事靠近保护`
  - `多屏聚焦`

## 摄像头页下方场景区

摄像头页 hero 下方推荐放“场景模板 + 能力说明”，不要继续堆设备参数。

推荐模板：

1. `离席隐私`
   - 离席暂停语音
   - 回席恢复
   - 第二人出现开启隐私屏

2. `Vibe Coding 手势`
   - 长眨激活
   - OK 确认
   - 摇头取消

3. `视线确认发送`
   - 看向右下进入发送确认
   - OK 或长眨发送
   - 摇头取消

4. `多屏聚焦`
   - 视线区域切换提示位置
   - 看左 / 右屏调整语音目标
   - 仅作为辅助，不自动提交内容

## 数据结构建议

当前已有 `cameraPrefs.presenceActions`，后续可以扩展为更通用的视觉流程配置：

```json
{
  "cameraPrefs": {
    "visionFlow": {
      "enabled": true,
      "triggers": {
        "away": {
          "enabled": true,
          "holdMs": 3000,
          "cooldownMs": 1200,
          "action": "pauseVoice"
        },
        "return": {
          "enabled": true,
          "holdMs": 1000,
          "action": "resumeVoice"
        },
        "shakeHead": {
          "enabled": true,
          "holdMs": 0,
          "cooldownMs": 1200,
          "action": "voiceCancel"
        },
        "longBlink": {
          "enabled": false,
          "holdMs": 300,
          "action": "voiceConfirm"
        },
        "okGesture": {
          "enabled": false,
          "holdMs": 1000,
          "action": "voiceConfirm"
        }
      },
      "gazeZones": {
        "enabled": false,
        "sendZone": {
          "zone": "bottomRight",
          "dwellMs": 1200,
          "action": "prepareSend"
        },
        "cancelZone": {
          "zone": "left",
          "dwellMs": 900,
          "action": "voiceCancel"
        }
      }
    }
  }
}
```

动作层建议使用语义动作，再映射到底层快捷键或 IPC：

- `voiceActivate`
- `voiceConfirm`
- `voiceSend`
- `voiceCancel`
- `pauseVoice`
- `resumeVoice`
- `privacyScreen`
- `prepareSend`

## 与现有代码的落点

- `src/index.html`：摄像头页 hero 结构、场景模板区、习惯页摄像头入口。
- `src/css/app.css` 或新增 `src/css/camera-workflow.css`：三段式布局、触发卡、动作卡、视线区域。
- `src/js/features/camera/camera-presence-actions.js`：把现有 action 从 `pressEsc / pressCtrlI` 扩展为语义动作。
- `src/js/features/camera/camera-preview.js`：复用现有 preview、gaze overlay、calibration 状态。
- 新增 `src/js/features/camera/camera-workflow.js`：负责视觉流程配置、UI 渲染、状态摘要和习惯页同步。

## 推荐结论

摄像头 hero 应该参考按键页的三段式，但命名和职责要改良：

`按键页：触发 -> 打开语音 -> 收尾`

`摄像头页：视觉触发 -> 执行动作 -> 视线管理`

这样用户会感觉自己是在配置一条自然的视觉工作流，而不是在调试摄像头算法。
