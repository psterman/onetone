# OneTone 首页能力探索与快速配置方案

## 1. 产品目标

OneTone 首页的任务不是展示技术模块，也不是要求用户完成全部配置，而是帮助用户尽快获得一个可验证的实际收益：

> 按下用户习惯的按键，OneTone 自动找到真实输入框、启动用户选择的语音输入方式，并将语音结果保留在输入框中。

核心体验指标是 **减少操作次数**。相比传统语音输入或手写输入，用户不再需要反复点击输入框、切换输入方式或重新寻找工作位置。

首页同时承担能力探索入口的职责：告诉用户已经获得了什么能力、补齐哪个环节可以进一步增强，以及哪些能力适合根据硬件和使用场景继续探索。

---

## 2. 核心产品原则

### 2.1 保留用户原有习惯

- OneTone 不替用户选择语音输入法。
- OneTone 学习并沿用用户已经形成的启动按键、输入节奏和结束方式。
- 已完成的快速入门配置不会在首页被重复询问。
- 能力链不完整时，已经可用的部分仍然保留。
- 用户可以随时修改方案、重新试跑或恢复上一个可用版本。

### 2.2 先让用户获得收益，再解释系统

首页默认只回答三个问题：

1. 现在已经能做什么？
2. 完成哪一步可以更顺手？
3. 点击后会获得什么？

Hook、Vosk、定位策略、状态回传等技术信息默认折叠在“查看详情”中。

### 2.3 不强制线性配置

- 快速入门不是进入首页的硬门槛。
- 用户可以使用已经获得的简化能力。
- 缺失环节应表达为能力升级，而不是系统故障。
- 用户可以自由进入 Soft Pad、语音、按键和摄像头路线探索。

### 2.4 用真实闭环验证能力

- 安装完成不等于能力已经获得。
- 能力必须在真实应用和真实输入框中试跑成功。
- 默认测试结果保留在输入框中，不自动发送。
- 验证成功后才记录为“已获得能力”。

## 3. 首个基础工作流

### 3.1 工作流定义

```text
用户按下习惯按键
    ↓
OneTone 识别当前前台应用
    ↓
定位真实输入框
    ↓
启动用户选择的语音输入方式
    ↓
用户说话并完成输入
    ↓
按当前结束策略处理
    ↓
默认将文字保留在输入框中
```

### 3.2 默认结束策略

首次安装且用户尚未配置时，默认：

> 结束语音输入后保留文字，不自动发送。

用户之后可以在全局方案或单个应用情景中选择：

- 保留文字
- 弹窗确认后发送
- 自动发送

### 3.3 输入框定位失败时

定位失败不能丢失用户刚才说的内容，也不能写入错误位置。

降级流程：

1. 继续完成语音识别。
2. 将文字安全暂存在 OneTone。
3. 不向任何应用写入。
4. 悬浮栏提示用户点击目标输入框。
5. 用户点击后自动补写。
6. 超时后保留为可恢复草稿。

## 4. 首次进入首页

### 4.1 首屏主动作

首次进入时提示用户主动运行一次系统测试：

> **检测我的起跑线**

测试的目的不是统计安装了多少工具，而是判断用户当前已经获得哪些能力，以及打通基础工作流还缺少哪些环节。

### 4.2 检测结果分类

不使用“成功 / 失败”制造压力，采用以下状态：

- **已经会用**：经过真实验证，可以立即使用。
- **还能更顺手**：当前能用，补齐后可以减少操作。
- **可以探索**：非必要，但能明显增强体验。
- **暂不适用**：缺少设备、权限或当前场景不需要。

### 4.3 推荐工作流

首次检测完成后，首页主角是一个可以马上获得收益的推荐工作流：

```text
少两步，直接开始说话

OneTone 可以帮你自动找到输入框并启动语音输入。
当前方案还需要补齐 2 项基础能力。

[快速配置并试跑]
```

推荐工作流优先于四通道地图和技术诊断详情。

## 5. 快速配置方案

### 5.1 适用范围

系统测试发现 Hook、Vosk 或其他基础依赖缺失时，生成一份快速方案。

快速方案包含：

- 完成后可以获得的能力
- 需要安装或修改的内容
- 预计所需时间
- 是否需要权限或应用重启
- 修改前创建的恢复点

### 5.2 执行原则

1. 用户查看简短方案。
2. 用户确认一次。
3. OneTone 自动完成安全、可恢复的配置。
4. 某一步失败时保留其他已经获得的能力。
5. 配置完成后立即进入真实应用试跑。
6. 用户可以反复修改方案、重新验证或恢复旧版本。

### 5.3 能力获得标准

基础工作流只有满足以下条件才算真正获得：

- 使用当前前台的真实应用
- 成功识别真实输入框
- 使用用户原来的启动按键
- 正常启动用户选择的语音输入方式
- 语音结果正确保留在输入框中
- 未发生错误发送
- 用户确认结果符合预期

## 6. 全局方案与应用情景

### 6.1 两级配置模型

#### 全局方案

- 所有应用默认继承。
- 保存用户基础输入习惯。
- 定义默认按键、定位行为和结束策略。
- 未建立个性配置的应用始终可以工作。

#### 应用情景

- 只有用户主动配置应用时才创建。
- OneTone 根据 Windows 当前前台应用自动加载。
- 可以覆盖全局按键、命令、输入位置和发送策略。
- 不应在首次识别新应用时强迫用户配置。

### 6.2 应用切换策略

- 已配置应用：自动加载对应情景。
- 未配置应用：继续使用全局方案。
- 无法确定应用时：低风险输入动作回退到全局方案。
- 无法确定应用时：高风险 Agent 管理动作暂停并确认。

### 6.3 自定义应用教学

OneTone 尚未支持的应用允许用户通过“点击一次输入框”进行教学。

每个应用最多保存两个输入位置，输入位置由用户根据情景自行定义，例如：

- 普通聊天
- Composer
- 命令栏
- 搜索框
- 备注区

每个位置保存：

- 用户定义的名称
- 定位方式
- 使用的启动按键
- 结束与发送策略
- 对应的 Agent 动作
- 最近一次验证结果

如果两个位置同时存在且无法明确判断，默认使用该应用上次成功使用的位置；定位失败或置信度不足时再提示用户选择。

## 7. 四条能力探索路线

通道不是技术诊断项目，而是用户掌控 Agent 的四种能力路线。

### 7.1 按键路线：基础能力

帮助用户：

- 使用原有按键启动语音输入
- 自动定位真实输入框
- 减少点击和切换操作
- 使用鼠标侧键、手柄或其他外设控制

首页表达示例：

> **已经会用**  
> 按下习惯按键即可开始语音输入。

### 7.2 Soft Pad 路线：第一推荐增强

帮助用户：

- 查看 Agent 当前状态
- 点击暂停、继续、确认和取消
- 编辑能力卡
- 为不同应用和 Agent 组织控制能力

基础语音输入打通后，Soft Pad 是第一项推荐探索能力。

### 7.3 语音控制路线

当麦克风可用时推荐：

- 用口令暂停 Agent
- 继续执行
- 确认或取消
- 在远离键盘时管理 Agent

语音输入和语音控制是两条不同能力链：

- 语音输入负责长内容输入。
- Vosk 等闭集口令负责 Agent 控制。

### 7.4 摄像头路线

仅在检测到摄像头时推荐：

- 摇头取消
- 离席暂停
- 回席继续
- 手势确认
- 双手被占用时控制 Agent

摄像头未开启不应影响其他能力，也不应降低总体可用判断。

### 7.5 推荐顺序

```text
按键启动语音输入
    ↓
Soft Pad 管理 Agent
    ↓
麦克风可用时推荐语音控制
    ↓
检测到额外按键或外设时推荐实体控制
    ↓
检测到摄像头时推荐手势能力
```

该顺序只是推荐，不限制用户自由探索。

## 8. 检测与增量验证

### 8.1 首次检测

- 用户主动点击后运行完整系统测试。
- 判断基础能力、依赖和硬件情况。
- 生成推荐工作流和探索建议。

### 8.2 后续进入首页

后续不重复运行完整启动检测：

- 立即展示上次已验证结果。
- 后台检查发生变化的设备、应用和配置。
- 某项执行失败时，只重新验证相关能力链。
- 保留“重新完整检测”按钮。
- 检测过程不阻塞已经可用的能力。

### 8.3 检测层级

首页不直接展示技术探针，而是将结果映射到用户能力：

| 技术检测 | 用户看到的能力结果 |
|---|---|
| 输入框定位可用 | 可以一键直接说话 |
| Hook 已连接 | 可以查看和管理 Agent 状态 |
| Vosk 可用 | 可以用口令控制 Agent |
| Soft Pad 已连接 | 可以点击管理 Agent |
| 摄像头已启用 | 可以使用手势和离席控制 |

## 9. 即时反馈

提示音和悬浮栏已经存在，首页不重复设计反馈系统，只负责验证它们是否正常工作。

悬浮栏阶段：

```text
正在定位
    ↓
可以说话
    ↓
正在输入
    ↓
已保留
```

重要结果不能只依靠瞬时 Toast，应在原位置保留：

- 执行了什么
- 是否成功
- 结果写入哪里
- 是否可以撤回
- 下一步是什么

## 10. 安全与撤回机制

### 10.1 动作分类

#### 可撤回动作

- 切换情景
- 修改绑定
- 自动对焦
- 输入测试文字
- 修改能力卡

执行后提供撤销和恢复点。

#### 不可逆或高风险动作

- 自动发送消息
- 终止 Agent
- 确认可能修改或删除用户数据的操作
- 执行会打断用户工作流习惯的动作

### 10.2 二次确认

高风险动作需要二次确认：

- 语音或摄像头发起动作
- 按键或 Soft Pad 完成第二次确认
- 确认前展示影响
- 超时后自动取消
- 能撤回的动作仍然提供即时撤回

## 11. 阶段称号与探索积分

首页使用阶段称号帮助用户理解成长过程，避免用百分比制造完成压力。

建议阶段：

1. **基础输入**：完成按键语音输入。
2. **Agent 控制**：Soft Pad 可以管理 Agent。
3. **多通道协作**：至少两种控制方式可用。
4. **情景适配**：建立应用专属工作流。
5. **全局匹配**：多应用、多动作能够自动切换。

能力积分初期只用于引导：

- 只奖励真实试跑成功的能力链。
- 不用于锁定功能。
- 不强迫用户配置不需要的设备和通道。
- 后期可以补充勋章和成就系统。

## 12. 首页信息架构

### 12.1 信息优先级

1. 当前应用情景，轻量显示。
2. 一个能够马上获得收益的推荐工作流。
3. 用户已经获得的能力。
4. 最值得探索的下一项能力。
5. Soft Pad、语音、按键和摄像头探索路线。
6. 系统检测与技术详情，按需展开。

### 12.2 首屏示例

```text
当前使用：全局方案

少两步，直接开始说话

OneTone 可以帮你自动找到输入框并启动语音输入。
当前方案还需要补齐 2 项基础能力。

[快速配置并试跑]

已经获得
按键触发 · 悬浮栏反馈 · 安全保留文字

完成后你将获得
一键定位 · 直接说话 · 少两次操作
```

### 12.3 探索区示例

```text
最值得探索
Soft Pad 管理 Agent
查看状态并点击暂停、继续、确认和取消
[快速配置]

其他路线
语音控制：麦克风可用，可以探索
实体控制：检测到鼠标侧键，可以探索

```

### 12.4 能力卡内容规则

每张能力卡默认只展示：

- 能帮用户完成什么
- 当前是否可以使用
- 补齐后能获得什么
- 唯一明确的下一步

技术详情折叠展示：

- Hook 状态
- Vosk 状态
- 输入框定位策略
- Windows 权限
- Agent 状态回传
- 最近一次验证证据

## 13. 总体产品定义

OneTone 首页不是设置中心，也不是传统系统检测页。

它是一张根据用户习惯、Windows 配置、硬件能力和应用情景生成的个性化能力探索地图。

首页首先帮助用户获得一个立刻可感知的收益：

> 少做操作，直接开始语音输入。

在此基础上，再引导用户逐步获得 Soft Pad、语音口令、实体按键和摄像头手势等 Agent 管理能力，最终形成能够根据应用自动切换的全局工作流。
