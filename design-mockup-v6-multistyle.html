多画风主题系统 · 品牌色统一

同一个 voice-pilot，三种完全不同的视觉语言 —— 但品牌色（蓝）贯穿所有主题，确保用户切换主题后还是"同一个产品"。架构采用 设计 Token 三层分离：品牌层（共用）+ 主题层（每主题独立）+ 组件层（不感知主题）。

03

实现架构 · 设计 Token 三层

给开发看的 · 组件层不感知主题
① BRAND TOKENS · 品牌层 所有主题共用
--brand-blue --brand-blue-2 --brand-blue-soft --brand-blue-glow
--state-success --state-warn --state-error --state-listen = --brand-blue
--logo --brand-voice (logo 气质)
② THEME TOKENS · 主题层 每主题独立
.theme-terminal {
--bg: #0d1117;
--surface: #161b22;
--text: #c9d1d9;
--border: #30363d;
--font: 'JetBrains Mono';
--radius: 4px;
--wave: ascii;
}
.theme-raycast {
--bg: rgba(28,28,30,.95);
--surface: rgba(255,255,255,.05);
--text: #fff;
--border: rgba(255,255,255,.08);
--font: 'Inter';
--radius: 12px;
--wave: bar;
}
.theme-ios {
--bg: #F2F2F7;
--surface: #FFFFFF;
--text: rgba(0,0,0,.88);
--border: rgba(60,60,67,.12);
--font: 'SF Pro Text';
--radius: 14px;
--wave: line;
}
③ COMPONENTS · 组件层 不感知主题 · 只消费 token
/* Button · 不管自己在哪个主题 */
.btn-primary {
background: var(--brand-blue);
color: white;
padding: 10px 18px;
border-radius: var(--radius);
font-family: var(--font);
box-shadow: 0 0 12px var(--brand-blue-glow);
}

组件只引用 token，不写死颜色 / 字体 / 圆角。换主题 = 换顶层 className = 整个组件树自动重渲染。

关键：--accent 在所有主题都引用 --brand-blue，所以用户改品牌色（v2 扩展）= 所有主题同步换色。

05

取舍 · 我建议先做 2 个

iOS 留 v2，不是不要
建议
v1 · Terminal + Raycast

两个都是深色，技术用户覆盖完整。开发工作量适中，每个主题都能做到 90 分。Raycast 主题顺便把"命令面板"的产品形态做出来。

不建议 · v1
iOS 主题留到 v2

iOS 主题在 Tauri 上的工作量大：阴影系统、圆角一致性、状态码语义、动效曲线全部要单独调。三个主题同时做，每个都半成品。

扩展性
用户自定义品牌色 · v2 后期

Token 架构支持未来扩展"自定义品牌色"。把 --brand-blue 改成用户选的颜色，所有主题同步换色。等于把整套主题系统做成"主题 + 配色"二维矩阵。

社区生态
v3 · 允许用户自制主题

把 Token 表导出成 JSON，让用户能 fork / 上传主题到 GitHub。Notion / VS Code 都是这么做出生态的。需要写一份 Token 文档 + 示例主题包。
